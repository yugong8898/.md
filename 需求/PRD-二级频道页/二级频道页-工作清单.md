## 1. 范围与整体架构

### 1.1 负责范围

二级频道页配置表单（`form/index.vue`，组件名 `SecondaryChannelForm`）通过注册表 `form/module-registry.ts` 挂载 **11 个模块**，按左侧导航分两组渲染：

| 分组 | 模块 key | 模块名 |
|---|---|---|
| 页面展示模块 | `top_banner` | 顶部轮播 Banner |
| 页面展示模块 | `category-list` | 类目列表 |
| 页面展示模块 | **`agent-market`** | **智能体市场** ← 本文档 |
| 页面展示模块 | **`activity-zone`** | **活动专区** ← 本文档 |
| 页面展示模块 | `latest-services` | 最新服务产品 |
| 页面展示模块 | `recommended-services` | 推荐服务产品 |
| 页面展示模块 | **`industry-news`** | **行业资讯** ← 本文档 |
| 页面展示模块 | `bottom_banner` | 底部 Banner |
| 页面展示模块 | `footer` | 底部配置 |
| 其他配置 | `seo` | SEO 设置 |
| 其他配置 | `publish` | 发布配置 |

**本文档只覆盖加粗的三个内容运营模块**：`agent-market` / `activity-zone` / `industry-news`，源码位于 `form/modules/<模块>/`。其余模块（含 `category-list`，负责人罗永江）不在本文范围。

### 1.2 边界

- **配置表单**（编辑 / 查看）：`form/index.vue` + 各模块 `form/modules/<模块>/index.vue`，数据挂在 `formData.modules[<moduleKey>]`。
- **详情 / 查看展示页**：由 `components/detail/DetailModuleRenderer.vue`（组件名 `DetailModuleRenderer`）按 `module.type` 分支渲染，共 10 种类型：`banner-list` / `category-grid` / `card-grid` / `activity-zone` / `service-summary` / `service-tags` / `article-list` / `single-banner` / `footer` / `info-grid`。它消费的是 `SecondaryChannelDetailModule`（`module.type` / `module.enabled` / `module.fields` 等），**与表单模块组件、表单数据结构完全独立**，不复用 `index.vue` / `readonly.vue`。
- 因此本文所述「只读态」均指**配置表单在 `mode=view` 或无编辑权限时的形态**（见 1.4），不是详情展示页。

### 1.3 模块接入契约

每个模块在 `module-registry.ts` 中登记为一条 `SecondaryChannelModuleConfig`：

```ts
interface SecondaryChannelModuleConfig {
  key: string;                 // 模块 key，与 formData.modules 的键、submit 的 apiKey 一致
  label: string;               // 左侧导航名称
  component: Component;        // 编辑/只读共用的主组件（index.vue）
  readonlyComponent: Component;// 只读组件（readonly.vue）——表单外壳实际不渲染，见 1.4
  validate: ModuleValidateFn;  // 提交审核前校验
  buildPayload: ModulePayloadBuilder; // 组装提交 payload
}
```

`module-types.ts` 定义的契约类型：

| 类型 | 签名 | 说明 |
|---|---|---|
| `ModuleValidateResult` | `{ valid: boolean; message?: string }` | 校验结果，`message` 为不通过提示 |
| `ModuleValidateFn` | `(formData) => Promise<ModuleValidateResult>` | 各模块 `validate.ts` 导出 `validateModule` |
| `ModuleApiPayload` | `{ apiKey: string; data: unknown; overridesBaseline: boolean }` | 提交数据块 |
| `ModulePayloadBuilder` | `(formData) => ModuleApiPayload \| null` | 各模块 `submit.ts` 导出 `buildModulePayload` |
| `validateEmptyModule` | `() => Promise<{ valid: true }>` | 空模块占位校验 |

**外壳调度**（`form/index.vue`）：

- 提交审核 `handleSubmit` → 先 `validateModules()`：按注册表顺序逐个 `await module.validate(formData)`，任一不通过即把 `activeModuleKey` 切到该模块并 `ElMessage.warning(result.message)`，中断提交。
- 存草稿 / 提交都会 `buildFullConfig(formData, baselineConfig, SECONDARY_CHANNEL_MODULES)`（`form/build-api-config.ts`）汇总各模块 `buildPayload` 产出的 `ModuleApiPayload`，再调 `saveCategoryChannelDraft`；提交额外调 `submitCategoryChannelReview`。

### 1.4 编辑态 / 只读态机制

**关键事实：表单外壳永远只渲染 `activeModule.component`（即各模块 `index.vue`），且不给它传任何 props。**

```vue
<!-- form/index.vue -->
<component :is="activeModule?.component" v-if="activeModule" :key="activeModuleKey" />
```

```ts
const mode = computed(() => String(route.query.mode || 'edit'));
const readonly = computed(() => mode.value === 'view' || !canEdit.value);
```

- 只读判定：路由 `mode === 'view'`，或工作台回显的 `canEdit === false`。
- `readonly` 经 Context 下发（1.5），各模块 `index.vue` **在自身模板内用 `context.readonly` + `v-if="!readonly"` / `:disabled="readonly"` 切换编辑控件与只读展示**，同一份 `index.vue` 兼顾两态。
- 注册表里的 `readonlyComponent`（各模块 `readonly.vue`）**在表单流程中从不被渲染**；三个内容模块的 `readonly.vue` 目前均为占位桩：`<DrawerSection :title> + <el-empty description="XXX只读展示待开发" />`，虽声明了 `data` prop 但未使用。

### 1.5 Context 数据流

模块不持有本地数据副本，全部经注入的 Context 读写。`form/index.vue` 通过 `provide(SECONDARY_CHANNEL_FORM_KEY, formContext)` 下发，模块用 `useSecondaryChannelFormContext()`（`form/composables/`）获取：

```ts
interface SecondaryChannelFormContext {
  formData: SecondaryChannelFormData;      // reactive，modules 挂各模块数据
  categoryId: Ref<string>;                 // 一级类目 ID（十进制字符串），活动候选接口入参
  readonly: Ref<boolean>;                  // 见 1.4
  changeStatus: Ref<SecondaryChannelChangeStatus>;
  publishStatus: Ref<SecondaryChannelPublishStatus | ''>;
  canEdit: Ref<boolean>;
  getModuleData: <T>(key: string) => T | undefined;  // 读 formData.modules[key]
  setModuleData: (key: string, data: unknown) => void; // 写 formData.modules[key]
}
```

三个模块 `index.vue` 统一的数据读写范式：

```ts
const { readonly, getModuleData, setModuleData } = useSecondaryChannelFormContext();

// 读：每次从 context 取并 normalize 兜底（后端回显缺字段也不炸）
const moduleData = computed(() =>
  normalizeXxxModuleData(getModuleData<XxxModuleData>(XXX_MODULE_KEY) ?? createDefaultXxxModuleData()),
);

// 写：合并式写回，只改传入字段
function patchModuleData(partial: Partial<XxxModuleData>) {
  setModuleData(XXX_MODULE_KEY, { ...moduleData.value, ...partial });
}

// v-model 桥接：computed get 读 moduleData，set 走 patchModuleData
```

每个模块 `types.ts` 都提供 `createDefaultXxxModuleData()`（新建初值 / 兜底基准）与 `normalizeXxxModuleData(raw)`（逐字段合并默认值、数组守卫、`showMoreEnabled ?? Boolean(moreLink.trim())`）。

## 2. 公共件

### 2.1 组件与工具清单

位于 `form/modules/components/` 与 `form/composables/`，三模块共用。

| 文件 | 组件名 / 导出 | 职责与关键实现 |
|---|---|---|
| `ModuleHeader.vue` | `ChannelModuleHeader` | 模块头部：标题 + 副标题 + 启用开关（`el-switch` + 文案「已启用/已禁用」）+ 前台展示名称。props：`title`(必)、`subtitle?`、`enabled`(必)、`displayTitle?`、`placeholder?`、`showDisplayTitle?`(默认 true)、`readonly?`；emits：`update:enabled`、`update:displayTitle`。`showDisplayTitle=false` 时头部不渲染名称输入（活动专区用，名称改放服务卡内）。 |
| `DisplayTitleField.vue` | `ChannelDisplayTitleField` | 「前台展示名称」输入：`el-input` `maxlength=30`；`enabled && !readonly` 时挂 required 规则「请填写前台展示名称」，否则清空规则并禁用输入。props：`modelValue`(必)、`enabled`(必)、`readonly?`、`placeholder?`。被 `ModuleHeader` 与 `ServiceProductCard` 共用。 |
| `ShowMoreConfig.vue` | `ChannelShowMore` | 「查看更多」块：开关（label「展示"查看更多"」）+ 链接输入（`el-input` placeholder「https://」+ hint「点击查看更多时的跳转地址」）。props：`enabled`(必)、`moreLink`(必)、`disabled?`、`readonly?`；emits：`update:moreLink`、`update:enabled`。关闭开关只隐藏前台入口，**已填链接保留不清空**；编辑态挂 required「请填写查看更多链接」+ 格式校验「请输入正确的网址格式」。 |
| `DragHandleIcon.vue` | `ChannelDragHandleIcon` | 拖拽手柄六点图标：SVG `10×16`（`viewBox 0 0 10 16`，2 列 × 3 行 `r=1.5` 圆点），`fill: currentColor` 跟随父级颜色。实际使用方：`agent-market/index.vue`、`activity-zone` 的 `ActivitySelectCard` 与 `ServiceProductCard`（行业资讯无拖拽，未使用）。 |
| `link-validator.ts` | `validateChannelLink(link): boolean` | 链接格式校验，表单失焦与各模块 `validate.ts` 共用。规则：`DANGEROUS_PROTOCOLS = ['javascript:','vbscript:','data:']` 先拦；必须匹配 `/^https?:\/\//i`；`new URL()` 可解析且 `hostname` 含 `.` 且长度 > 1；空值 / 异常一律 `false`。 |
| `useDragSort.ts`（composables） | `useDragSort<T>(options)` | 列表行拖拽排序（原生 HTML5 DnD）。入参 `{ list: () => T[]; onReorder: (list: T[]) => void; canDrag?: () => boolean }`；返回 `{ rowDraggable, isDragging, dragIndex, renderList, handleHandleMousedown, handleDragStart, handleDragOver, handleDragEnd }`。按住手柄 `mousedown` 才置 `rowDraggable=true` 激活 `draggable`，拖拽中用本地让位列表 `renderList` 预览，`dragend` 一次性 `onReorder` 写回。收敛 agent-market 列表、activity-zone 活动卡、activity-zone 服务卡三处同构实现。 |

### 3.2 数据结构（types.ts）

`AgentCardDTO`（对应服务端 `CategoryChannelAgentCardDTO`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `agent_id` | `string` | 智能体 ID，`MANUAL` 来源时为空串 |
| `name` | `string` | 卡片展示名称 |
| `description` | `string` | 卡片展示描述 |
| `image` | `string` | 卡片图片 URL |
| `link` | `string` | 跳转链接 |

| `local_id` | `string` | 版本内稳定本地 ID，列表定位 / 编辑用 |
| `source_type?` | `'MANUAL' \| 'AGENT'` | 来源类型 |

| 常量 | 值 | 用途 |

| `AGENT_MARKET_MODULE_KEY` | `'agent-market'` | 模块 key |
| `AGENT_MAX_COUNT` | `3` | 手动配置数量上限 |

### 3.3 index.vue 结构

- **头部**：`ChannelModuleHeader` `title="智能体市场"`、`subtitle="手动配置最多 3 个智能体"`（模板用 `${AGENT_MAX_COUNT}`）、`placeholder="智能体市场"`、`v-model:enabled`、`v-model:display-title`、`:readonly`。
- **列表卡**（`:class="{ 'is-disabled': !enabled }"`，禁用时整体 `opacity: 0.55`）：
  - 卡头：计数「已配置 {items.length}/3 个智能体」+「新增智能体」按钮（`v-if="!readonly"`，`:disabled="!enabled || isMaxItems"`）。
  - 列表行（`v-for="renderList"`，`:key="local_id"`，`useDragSort` 拖拽）：拖拽手柄（`v-if="!readonly"`）→ 封面（`el-image` 有图 / `未配置` 占位，CSS 尺寸 **96×64**）→ 名称 + 简介（`description || '—'`）→ 操作（`v-if="!readonly"`：仅「编辑」「删除」两个 link 按钮，`:disabled="!enabled"`）。
  - **行内无状态标签（`el-tag`）、无行内启用开关**；卡片启用状态只在编辑弹窗内切换。
  - 空列表：`el-empty description="暂无智能体"`。
- **查看更多**：`ChannelShowMore` `:disabled="!enabled"` `:readonly`。
- **弹窗**：`AgentEditDialog` `v-if="!readonly"`。
- 交互：`openAddDialog` 达上限时 `ElMessage.warning("最多配置 3 个智能体")`；`handleDelete` 二次确认「确认删除该智能体？删除后前台不再展示。」；`handleSaveAgent` 编辑按 `local_id` 合并、新增补 `{ agent_id: '', local_id, source_type: 'MANUAL' }`；`createLocalId()` = `agent-${Date.now()}-${随机}`。

### 3.4 AgentEditDialog.vue

`el-dialog`（标题「编辑智能体」/「新增智能体」，宽 720px，`label-position="top"`）：

| 字段 | 控件 | 约束 |
|---|---|---|
| 智能体名称 `name` | `el-input` `maxlength=999` | 必填「请填写智能体名称」(blur) |
| 智能体简介 `description` | `el-input` `type=textarea` `rows=3` `maxlength=100` | 非必填 |
| PC 端封面图 `image` | `MaterialImageUpload` `:image-size={width:800,height:600}` | **非必填**（无校验规则） |
| 跳转链接 `link` | `el-input` placeholder「https://」 | 选填；有值则格式校验「请输入正确的网址格式」(blur) |
| 启用此智能体 `enabled` | `el-switch` | 新增默认 `true` |

- 封面裁剪尺寸常量 `AGENT_COVER_IMAGE_SIZE = { width: 800, height: 600 }`（4:3）。
- `save` 事件抛 `Omit<AgentCardDTO, 'agent_id' | 'local_id' | 'source_type'>`（即 `{ name, description, image, link, enabled }`，`id`/顺序由父组件补）；校验不通过不关弹窗；每次打开重新回填、关闭清错误态。

### 3.5 校验规则（validate.ts，共 6 条）

按顺序短路返回，先 `normalizeAgentMarketModuleData` 兜底：

| # | 规则 | 不通过提示 |
|---|---|---|
| 1 | 模块禁用（`!enabled`）直接通过，不校验内部字段 | — |
| 2 | 启用时前台展示名称必填 | 请填写前台展示名称 |
| 3 | 智能体数量 ≤ `AGENT_MAX_COUNT`(3)（兜底） | 智能体最多配置 3 个 |
| 4 | 每个智能体名称必填 | 存在未填写名称的智能体 |
| 5 | 跳转链接有值时格式必须合法（`validateChannelLink`） | 智能体跳转链接格式不正确 |
| 6 | 开启查看更多时 `moreLink` 必填且格式合法 | 请填写查看更多链接 / 查看更多链接格式不正确 |

> **无「最少数量」校验**：启用时 `items` 允许为空（与行业资讯「至少 1 篇」不同）。「固定配置 3 个」是否需强制 `min=3` 见第 7 章 TODO。

### 3.6 提交 payload（submit.ts）

```ts
{
  apiKey: 'agent-market',   // = AGENT_MARKET_MODULE_KEY
  data: {
    name, enabled,
    items: [{ agent_id, description, enabled, image, link, local_id, name, source_type }],
    moreLink,
  },
  overridesBaseline: false,

```

### 3.7 只读态

`readonly.vue` 为占位桩（`el-empty description="智能体市场只读展示待开发"`），表单不渲染。实际只读态由 `index.vue` 靠 `context.readonly` 收敛：隐藏新增 / 编辑 / 删除 / 拖拽手柄，`ChannelModuleHeader` 与 `ChannelShowMore` 的开关和输入转 `:disabled`。

## 4. 活动专区（activity-zone）

活动专区由**活动选择**与**服务产品选择**两块组成，二者强关联：服务产品数据源依赖已选活动，活动集合变化会清空已选服务。

### 4.1 文件构成

```
form/modules/activity-zone/
├── types.ts / validate.ts / submit.ts / index.vue / readonly.vue
└── components/
    ├── ActivitySelectCard.vue    # 活动选择卡（Banner 开关 + 活动表格 + 拖拽）
    ├── ActivitySelectDialog.vue  # 添加活动弹窗（活动候选检索）
    └── ServiceProductCard.vue    # 服务产品卡（展示名 + 内联选择 + 已选拖拽）
```

### 4.2 数据结构（types.ts）

`ActivityBannerDTO`（对应服务端 `v1.ActivityBannerDTO`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `activityId` | `string` | 活动 ID（十进制字符串） |
| `name` | `string` | 活动名称 |
| `image` | `string` | 频道页展示图（运营上传），开启 Banner 时必填 |
| `link?` | `string` | 活动详情跳转链接，运营可编辑、选填 |
| `status?` | `string` | 未开始 / 进行中，检索带回 |
| `startTime?` / `endTime?` | `string` | 活动起止时间 |
| `productScopeName?` | `string` | 服务适用范围文案 |

    enabled, name,
    items,       // 整份 IndustryNewsItemDTO[]（不裁剪字段）

  },

## 6. 接口对接

两个候选检索接口均位于 `api/secondary-channel/`，走企服网关（`UrlPrefixEnum.ESP`），响应用 `isEspConsoleEnvelopeSuccess` 判成功 + `resolveEspModelOrData` 解信封（`@/utils/esp-console-envelope`），失败抛错、空数据兜底 `{ count: 0, list: [] }`。

### 6.1 活动候选 category-activities-api.ts

- **接口**：`GET /api/v1/admin/category-channels/options/category-activities`
- **函数**：`getCategoryActivityOptions(params: CategoryActivitiesQuery): Promise<CategoryActivityOptionListData>`
- **调用方**：`ActivitySelectDialog.vue`（添加活动弹窗）。

入参 `CategoryActivitiesQuery`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `category_code` | `string` | 一级类目 ID（十进制字符串），必传，来自 Context `categoryId` |
| `keyword?` | `string` | 活动名称模糊匹配 |
| `page?` | `number` | 页码，默认 1 |
| `page_size?` | `number` | 每页条数，默认 5，最大 100 |
| `selected_ids?` | `string[]` | 跨页回显已选活动 ID，**重复 query key** 传递 |

出参 `ActivityOptionDTO`（信封 `{ count, list }`）：`activity_id?` / `name?` / `status?`（未开始 / 进行中）/ `start_at?` `end_at?`（RFC3339）/ `employer_scope_type?`（已认证雇主 / 指定雇主 / 未认证雇主）/ `service_scope_type?`（本接口恒「按类目选择」）/ `category_scope_paths?: CategoryChannelScopePathDTO[]` / `category_scope_summary?`（顿号连接）/ `selected?`（是否在 `selected_ids` 中）/ `banner_presentation?`（恒 `null`，D-022 主数据关闭）。

`CategoryChannelScopePathDTO`：`category_id?` / `category_level?`（1/2/3）/ `category_name?` / `category_path?: string[]`（从上到下完整路径）。

### 6.2 服务候选 activity-product-options-api.ts

- **接口**：`GET /api/v1/admin/category-channels/options/activity-products`
- **函数**：`getActivityProductOptions(params: ActivityProductsQuery): Promise<ActivityProductOptionListData>`
- **调用方**：`ServiceProductCard.vue`（服务产品内联面板）。

入参 `ActivityProductsQuery`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `activity_ids` | `string[]` | 活动 ID 列表，1~50 个，**重复 query key**，服务端去重 |
| `keyword?` | `string` | 服务名称关键字或精确服务编号 |
| `page?` | `number` | 页码，默认 1 |
| `page_size?` | `number` | 每页条数，**默认 20**，最大 100 |

> 接口默认 `page_size=20`，但 `ServiceProductCard` 调用时显式传 `SERVICE_PAGE_SIZE=5`。

出参 `ActivityProductOptionDTO`（信封 `{ count, list }`）：`product_id?`（雪花 ID 字符串）/ `name?` / `provider_id?` / `provider_name?` / `service_no?`（服务编号，展示与精确搜索）/ `leaf_category_id?` `leaf_category_name?`（末级类目）/ `related_activities?: RelatedActivityDTO[]`（限入参 `activity_ids` 且当前可用，按 `activity_id` 升序）/ `user_scope_types?: string[]`（升序去重，多活动人群不同时多值）。

`RelatedActivityDTO`：`activity_id?` / `activity_name?` / `user_scope_type?`（已认证雇主 / 指定雇主 / 未认证雇主）。

- **雪花 ID 保精度**：本接口额外展开 `ESP_SNOWFLAKE_JSON_AXIOS_CONFIG`（`@/utils/json-parse-snowflake-ids`），在响应解析阶段把 `product_id` / `provider_id` 等大整数按字符串处理，避免 JS number 丢精度（活动候选接口无此配置）。

### 6.3 遗留 mock 数据源

`form/modules/activity-zone/components/mock.ts`（506 行，导出 `PUBLIC_ACTIVITYS` / `PUBLIC_PRODUCTS`）为接入真实接口前的旧数据源，**当前已完全孤立**：仅在 `ServiceProductCard.vue` 中以注释形式保留追溯（`// import { PUBLIC_PRODUCTS } from './mock'`），无任何存活 import；代码中**不存在 `USE_ACTIVITY_SELECT_MOCK` 之类开关常量**。详见附录。
