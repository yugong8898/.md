## 1. 需求概述

在运营后台新建「二级频道」配置与审核体系：运营人员按一级类目（共 11 个，一一对应、最多一个频道）配置频道页的 9 个展示模块 + SEO 设置 + 发布配置，经「初审 → 复审」两级审核后，按立即发布 / 定时发布规则上线，支持定时下线、手动下线与发布异常重试。

- 需求来源：`.md/需求/PRD-二级频道页/PRD-二级频道页.md`（V1.0）
- 适用端：运营后台（PC 端）；雇主端前台为另一侧范围，不在本文档内
- 所属项目：`ai-platform/es-ops-platform`（企服线，Vue 3 + TS + Element Plus，规范以项目自带 `AGENTS.md` 为唯一事实源，不适用 WLYD 物流线规范）
- 个人分工与任务拆解见同目录《二级频道页-工作清单（内容运营模块）》

## 3. 业务规则

### 3.1 频道与类目关联

- 一个一级类目最多关联一个二级频道页，一个频道只关联一个一级类目。
- 一级类目固定 11 个：AI 与数据智能、法律服务、工商财税、跨境企服、品牌与设计、企业综合服务、人力资源服务、软件与信息化、数字资产与知产交易、营销推广、知识产权。
- 只有「已发布」的频道才对雇主端生效；未配置频道的类目保留原一级类目列表页逻辑（雇主端侧）。

### 3.2 状态机（前端口径已定义于 `constants.ts`）

| 状态组 | 枚举值 → 文案 |
|--------|--------------|
| 线上发布状态 | `unpublished` 未发布 / `published` 已发布 / `offline` 已下线 / `publish_failed` 发布异常 |
| 变更状态 | `none` 无待处理变更 / `draft` 存在草稿 / `pending_initial` 变更待初审 / `pending_secondary` 变更待复审 / `rejected` 审核驳回 |
| 审核状态 | `pending_initial` 待初审 / `pending_secondary` 待复审 / `rejected` 已驳回 / `approved` 已通过 |

> 定时发布场景的「待发布 / 已发布」变更态 PRD 第 7 章未展开，枚举是否需要扩展见待确认 #2。

### 3.3 列表页操作规则

| 操作 | 展示条件 | 行为 |
|------|---------|------|
| 查看线上配置 | 线上状态 = 已发布 | 进入线上配置只读页，展示线上快照；审核中的待发布内容不展示 |
| 查看进度 | 所有频道 | 进入变更进度只读页：变更单号、变更内容、提交说明、提交人/时间、初审意见、复审意见、待发布配置 |
| 编辑 | 仅受变更状态控制 | 待初审/待复审时置灰不可编辑 |
| 下线 | 线上状态 = 已发布 | 确认弹窗（展示一级类目 + 三行影响说明，按钮「取消｜确认下线」）→ 状态转已下线，快照保留，草稿与审核中变更不删除 |
| 重新发布 | 线上状态 = 发布异常 | 按立即发布处理：状态转已发布、立即生效、更新最后修改时间、**不重新审核**；toast「重新发布成功，频道已立即生效」 |

### 3.4 审核规则（六条铁律）

1. 新建和编辑均必须提交审核；
2. 不支持提交后撤回；
3. 待初审、待复审状态不可编辑配置；
4. 驳回后可修改重新提交；
5. 初审与复审必须由不同角色完成；
6. 不允许跳过初审直接进入复审。

- **初审**：通过/驳回均流转至复审；驳回意见必填；通过时意见可不填。提示文案分别为「初审通过意见已提交，已流转至复审」「初审驳回意见已提交，已流转至复审」。
- **复审**：结论与初审一致 → 意见免填，初审结论作为最终结果；不一致 → 复审意见必填，最终以复审为准。
- 最终通过 → 按发布配置执行（立即发布：待发布配置立即同步线上；定时发布：记录计划时间，到时自动上线）。
- 最终驳回 → 不更新线上配置，变更单转「审核驳回」，可修改后重新提交。

### 3.5 发布配置规则

- 发布时间必选：审核通过时已超过发布时间 → 立即上线；未到发布时间 → 待发布状态，到时自动上线。
- 审核中的变更单不支持修改发布时间，页面展示审核中提示。
- 定时下线可选：不设置则持续展示（可列表页手动下线）；设置则下线时间必须晚于发布时间，否则不可提交。
- 提交审核说明必填，同步展示于审核列表、初审页、复审页、查看进度页。

### 3.6 配置页模块清单与规则

左侧导航两组：**页面展示模块**（顶部轮播 Banner、类目列表、智能体市场、活动专区、最新服务产品、推荐服务产品、行业资讯、底部 Banner、底部配置）+ **其他配置**（SEO 设置、发布配置）。

通用模式：模块开关（关闭后数据保留，重新启用可继续使用）+ 前台展示名称（启用时必填）+「查看更多」开关（关闭后已填链接保留）。

| 模块 | 必填性 | 关键规则 |
|------|--------|---------|
| 顶部轮播 Banner | 可选模块 | 多条 Banner：名称（后台识别）+ PC 图片（必填）+ 跳转链接（必填）+ 展示顺序 + 生效/失效时间；新增默认启用，启用/禁用在列表操作列控制；前台最多展示 5 个启用且在有效期内的 |
| 类目列表 | **必填模块** | 两种形式：标准模式（读系统类目树，一/二/三级，不可增删改）；图片配置模式（手动添加：名称+图片+链接均必填，同名不可重复，支持编辑/删除） |
| 智能体市场 | 可选模块 | 智能体：名称必填，简介/封面/链接选填，展示顺序 + 启用状态；新增默认启用；后台最多 6 个（自动获取模式待定） |
| 活动专区 | 可选模块 | 「活动选择」+「活动服务产品」两区域独立配置；开启模块至少需选 N 个活动服务产品（N 待确认）；活动弹窗拉活动管理中「未开始+进行中」活动，按名称搜索，5 条/页，最多选 3 个；开启「展示活动 banner」时活动展示图片必填，关闭时添加按钮置灰；服务产品按名称/服务 ID 检索、5 条/页、最多 6 个、拖拽排序 |
| 最新服务产品 | 可选模块 | 系统自动获取，只配置：展示数量 + 排序方式（更新时间/上线时间）+ 查看更多 |
| 推荐服务产品 | **必填模块**（不可开关） | 手动选服务（按名称/编号搜索），同一服务只能加一次（重复提示），展示顺序可编辑排序、支持拖拽 |
| 行业资讯 | 可选模块 | 新增文章弹窗：封面图 + 文章名称（≤25 中文字符）+ 作者名称 + 跳转链接，均必填；后台最多 8 篇 |
| 底部 Banner | 可选模块 | 单图配置（新图覆盖旧图），启用时图片必填；跳转可选：无跳转 / 有跳转（链接必填） |
| 底部配置 | **必填模块**（不可开关） | 固定信息（可开关）：客服热线、人工服务起止时间（必填且结束 > 开始）、是否展示频道名称；底部内容模块：≤4 个小组，小组名称必填，每组 ≤6 条内容（内容名称必填、底部文字、跳转链接、拖拽排序），删小组连同内容一起删 |
| SEO 设置 | 随变更单提交 | SEO 标题（建议 ≤30 中文字符，超出仅提示不阻断）+ 关键词（英文逗号分隔）+ 描述（建议 ≤120 字，仅提示） |
| 发布配置 | **必填项**（不可开关） | 见 3.5 |

### 3.7 图片与链接通用规则

- 图片：仅支持 PNG / JPG / JPEG，单张 ≤ 20MB，上传成功后展示预览，加载失败展示缺省态。
- 跳转链接：需符合标准网址格式校验；禁止危险脚本链接（安全要求）；前台统一新窗口打开，后台不配置跳转方式。

### 3.9 提交审核校验（汇总）

提交审核时逐模块校验（已建的 `module-registry.ts` 校验链），失败阻断提交并定位到对应模块。已知必检项：

- 必填模块（类目列表/推荐服务产品/底部配置/发布配置）配置完整；
- 发布时间必填；设置定时下线时下线时间 > 发布时间；提交审核说明必填；
- 类目列表图片配置模式：前台展示名称已填、至少一条类目、每条有图片与链接、无重复类目；
- 活动专区：至少 N 个活动服务产品（N 待确认）；开启活动 banner 时至少 1 个活动且展示图片必填；
- 各模块启用时前台展示名称必填；底部固定信息启用时服务时间必填且结束 > 开始。

每个模块按既有三件套结构实现：`index.vue`（表单/列表/弹窗）、`types.ts`（数据结构）、`validate.ts`（按 3.9 校验项）、`submit.ts`（组装提交数据）。建议实现顺序见第 11 节。

## 10. 风险点

1. **mock 缓存陷阱**：`api/secondary-channel/index.ts` 的 `channelCache` 为模块级内存缓存，创建/下线仅改内存，刷新即丢失；联调切真实接口时整层重写，勿以 mock 行为作为测试结论。
2. **form 页身兼三职**：当前查看进度/编辑/审核均跳 form 页，与 PRD 页面模型不符，拆页前必须先定路由与入参约定，否则越堆越乱。
3. **状态机不完整**：定时发布链路（审核通过 → 待发布 → 上线）的变更状态未定义，影响列表展示与锁定逻辑。
4. **数量口径矛盾**：活动 Banner 上限（3 vs 不限）未锁定前不宜完成活动专区校验。
5. **配置页体量大**：11 个模块含多弹窗、拖拽、图片上传，是主要工作量；须沿用 `module-registry` 三件套，不绕开既有机制。
6. **接口全部未定**：字段名/路径不确定，前端先按 `types.ts` 契约开发并联调时集中替换，避免散落硬编码。

## 11. 开发顺序建议

1. 页面拆分与路由约定先行：progress / online / 初审 / 复审 / 审核查看 的路由与入参；
2. 列表页补齐：查看线上配置、重新发布、下线弹窗文案对齐；
3. 详情回显接口约定 + `formData` 填充链路（后续各模块开发的前置依赖）；
4. 11 个模块组件按依赖顺序实现：类目列表 → 顶部轮播 → 底部配置 → 推荐服务 → 最新服务 → 智能体 → 活动专区 → 行业资讯 → 底部 Banner → SEO → 发布配置；
5. 审核三页面（初审/复审/查看）+ 审核列表补列与待处理数量；
6. 只读页（查看进度 / 查看线上配置）——复用模块组件只读态；
7. 权限点接入、菜单挂载；
8. mock → 真实接口整体切换 + 按第 9 节清单回归。
