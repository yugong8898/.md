## 资料分类

| 目录 | 用途 | 当前内容 |
| --- | --- | --- |
| `待接入/` | 尚未识别需求编号的原始输入资料 | 空 |
| `进行中/` | 尚在处理或待确认的需求工作区；一级子目录仅使用需求编号 | `REQ-170`、`REQ-171` |
| `已完成/` | 已交付需求工作区；一级子目录仅使用需求编号 | `C103.3`、`C111.1`、`C146.9`、`C147.9`、`C149.5`、`C161`、`C169.6`、`C169.6-C187.8`、`C187.8`、`历史版本号` |
| `公共资料/` | 跨需求或不宜归属单一编号的方案、接口梳理与 PRD | `85.8`、`PRD-二级频道页`、`TMS结算业务梳理和迁移方案`、`前端撮合运单接口-梳理`、`费用明细重构方案` |
| `规范/` | 需求工作区及 workflow 的维护规则 | [需求工作区维护SOP](./规范/需求工作区维护SOP.md) |
| `归档/zip/` | 原始 ZIP 资料 | REQ-171 相关压缩包 |
| `归档/待确认副本/` | 文件名含 `copy` 或 `副本` 的资料，待人工确认保留策略 | 5 份 Markdown 副本 |
| `归档/历史版本/` | 不作为当前正式版本的完整目录 | `TMS结算业务梳理和迁移方案 2` |

## 维护规则

1. 已识别编号的原始资料放入 `进行中/<需求编号>/原始需求/`；未识别编号时先放入 `待接入/`。
2. `进行中/` 与 `已完成/` 的一级子目录只能使用需求编号；正式阶段产物使用 `阶段<序号>-<产物类型>-<需求编号>.md`。
3. 已完成时整体移动 `进行中/<需求编号>/` 至 `已完成/<需求编号>/`。
4. 副本、历史版本和压缩包只归档，不直接删除；确认无保留价值后再单独处理。
5. `TODO.md` 保持为本目录的待办入口；目录结构或分类发生变化时，同步更新本索引。
