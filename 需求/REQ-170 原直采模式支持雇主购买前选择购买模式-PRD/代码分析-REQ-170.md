## 四、提交与创建后流程

### 4.1 当前提交链

[buy.vue:980–1184](../../../ai-platform/es-web/src/views/employer/purchase/buy.vue#L980-L1184)：

```text
环境开关 → 认证 → 防重／参数／库存校验
→ 必要时补取用户信息 → 提交埋点 → submitting=true
→ 雇主功能校验 → 保证金匹配
→ 命中时等待“需要／不需要”
→ 创建 V2 订单 → 校验 res.ok 和 res.data.id
→ 写 currentOrderId → 按原 orderType 分流
→ finally 释放 submitting
```

创建接口：`POST /aira-aiplatform-esp-api/v2/employer/orders`，已有 `CreateEmployerOrderV2Params.orderType: number`。可选 `demandId`，不存在“类型为2就由前端补造需求ID”的要求。

除类型外，创建参数还包含雇主、商品、档位、数量、券、报价、商机和客服；用户选择需要保证金且字段齐备时补保证金参数。请求封装采用静默业务错误选项，由页面负责失败提示与刷新。

失败包含抛错、`res.ok=false`、成功响应缺少订单 ID；均不进入签约／支付，继续原刷新处理。

### 4.2 创建后的已有分支

| 原分支 | 当前行为 | REQ-170 影响 |
|---|---|---|
| `orderType === 2` | `void handleSignContract(orderId)` | 判断条件必须改用本次提交类型；合同逻辑复用 |
| `orderType === 1` 且实付为零 | 触发已有优惠券弹窗并跳订单详情，不开收银台 | 保留，只能用于实际创建类型为1的订单 |
| `orderType === 1` 且需支付 | `openEmployerOrderCashier`，透传订单 ID、雇主和待支付阶段 ID | 复用原收银台及支付结果处理 |
| 其他类型 | 兜底跳订单详情 | 不擅自改写 URL 异常类型或删除兜底 |

支付成功／处理中保留原成功处理；失败保留提示；取消／需刷新保留详情跳转。不重建这些流程。

## 五、需要纳入方案的边界

### 5.1 提交锁与保证金关闭

当前存在两个防重窗口：补取用户信息发生在加锁之前；命中保证金时在等待弹窗前设置 `submitting=false`。

[BondRequiredDialog.vue](../../../ai-platform/es-web/src/views/employer/purchase/BondRequiredDialog.vue) 的事件行为：

| 用户操作 | 子组件事件 | 父页当前结果 |
|---|---|---|
| 需要 | 先 `confirm(true)`，后 `update:visible(false)` | Promise 完成，带保证金继续创建 |
| 不需要 | 先 `confirm(false)`，后 `update:visible(false)` | Promise 完成，不带保证金继续创建 |
| 关闭图标／Modal cancel | 仅 `update:visible(false)` | 弹窗隐藏，`requestBondConfirmation` 的 Promise 仍未完成 |

新增全程锁时必须同时处理第三种情况，否则关闭后可能一直禁用。不能把关闭解释成“不需要保证金”并自动创建订单。这个边界可在父页接收已有可见性事件时处理，不必修改子组件或保证金接口。

### 5.2 进入与实例复用

- [路由注册](../../../ai-platform/es-web/src/router/routes/employer/purchase.ts) 未为确认页设置 keepAlive。
- 已搜索 `keepAliveStore.add`，命中服务大厅、售后、任务等，未见确认页注册缓存。
- [PortalLayout.vue:1761–1769](../../../ai-platform/es-web/src/layouts/portal/PortalLayout.vue#L1761-L1769) 的组件 key 使用 `resolveRouterViewCacheKey(viewRoute.path)`。
- [helper.ts:54–75](../../../ai-platform/es-web/src/router/helper.ts#L54-L75) 对确认页返回原 path；仅 query 变化时 key 不变。
- 确认页只有 mounted/unmounted 初始化，数量是 setup 时的 ref；仅补一个 checkbox 默认值不足以覆盖同路径不同商品／报价参数的重进。

阶段2需选择明确的局部重进策略，同时防止旧实例异步任务在离开后继续创建或跳转。不能为了本页将全站 key 一律改成 fullPath。

### 5.3 权限刷新、提交快照与已创建状态

- 新权限必须严格比较 `true`；字符串 `'true'`、数字 `1`、缺失均不能放行。
- 预览失败或刷新后撤权不能保留可提交的旧权限。实际创建类型也要做权限兜底，不能只靠隐藏 checkbox。
- 保证金等 await 之前取得本次类型快照；创建参数、成功分流和本页业务类型埋点必须一致。
- 当前创建成功后会保存 `currentOrderId`，但提交入口不据此阻止再创建；合同使用 `void` 调用，部分支付失败会留在本页。方案需明确已创建后的控件锁定与继续处理入口。
- 前端防重不等于服务端幂等。创建请求已发出后发生断网或离页，前端不能认定后台没有生成订单。
