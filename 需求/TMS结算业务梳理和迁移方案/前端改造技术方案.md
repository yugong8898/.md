# TMS 结算服务迁移 — 前端改造技术方案

> 项目：`fe-match-end/match-owner-pc/app-base`

## 一、现状分析

### 1.1 涉及文件清单（改造前）

| 文件路径 | 当前职责 | 前缀引用方式 |
|---------|---------|-------------|
| `src/config/project-config.ts` | 接口前缀配置 | 定义 `apiPrefixConfig.lmtUser = '/lmt-user'` |
| `src/service/index.ts` | http 封装（`@wlydfe/service`） | 默认 `urlGateway='/gateway'`、`urlPrefix=''`、`joinPrefix=true` |
| `src/api/reconciliation/index.ts` | 客户汇总/对账单/对账明细 | `const LMT_USER = apiPrefixConfig.lmtUser` → 模板字符串 |
| `src/api/financial-management/daily-income.ts` | 日常收入 | `${LMT_USER}/income/*` |
| `src/api/financial-management/daily-expense.ts` | 日常支出 | `${LMT_USER}/expenditure/*` |
| `src/api/inTransit/index.ts` | 在途费用（主） | `GATEWAY = { urlGateway: '/gateway/lmt-user' }` 传参 |
| `src/api/waybill/index.ts` | 在途费用（重复定义） | `${LMT_USER}/route-cost/*` |

### 1.2 http 调用机制（`@wlydfe/service`）

请求最终 url 由 `defaultBeforeRequestHook` 拼接（`joinPrefix=true` 时生效）：

```
最终 url = `${urlGateway}${urlPrefix}${config.url}`
```

- 默认 `urlGateway = '/gateway'`（`GatewayEnum.GATEWAY`）
- 默认 `urlPrefix = ''`（`UrlPrefixEnum.DEFAULT`）
- 请求级 `options`（http.post 第二参数）覆盖默认 `urlGateway`

**两种前缀写法最终路径等价**（关键结论，已源码确认）：

| 写法 | urlGateway | config.url | 最终路径 |
|------|-----------|-----------|---------|
| 前缀拼接（waybill） | `/gateway`（默认） | `/lmt-user/route-cost/cost-audit` | `/gateway/lmt-user/route-cost/cost-audit` |
| GATEWAY 传参（inTransit） | `/gateway/lmt-user` | `/route-cost/cost-audit` | `/gateway/lmt-user/route-cost/cost-audit` |

> 因此在途费用统一采用「前缀拼接」写法（`tmsUrl`），与 waybill 重复定义写法一致，最终请求路径不变。

### 1.3 前缀引用方式差异（改造前）

| 方式 | 文件 | URL 示例 | options 传参 |
|------|------|---------|-------------|
| A 变量拼接 | `reconciliation/index.ts` | `` `${LMT_USER}/lscWaybill/page` `` | 不传 |
| B 变量拼接 | `daily-income.ts` | `${LMT_USER}/income/page` | 不传 |
| C 变量拼接 | `daily-expense.ts` | `${LMT_USER}/expenditure/page` | 不传 |
| D GATEWAY 传参 | `inTransit/index.ts` | `/route-cost-query/cost-apply-list` | `{ urlGateway: '/gateway/lmt-user' }` |
| E 变量拼接 | `waybill/index.ts` | `${LMT_USER}/route-cost/cost-audit` | 不传 |

> 方式 A/B/C/E 的 URL 带 `/lmt-user` 前缀；方式 D 通过 `urlGateway` 参数指定。两种最终路径一致，拼装方式不同。改造后统一为「前缀拼接 + 开关动态前缀」。

### 1.4 页面层影响

改造在 **API 层完成**（前缀动态化），页面层调用签名与返回值不变，**20 个涉及页面/组件无需改动**。唯一页面层改动：5 个列表页 `onMounted` 接入开关刷新（见 2.3 逻辑4）。

### 2.3 关键逻辑设计

#### 逻辑1：开关 Store（`stores/tms-switch.ts`）

- 职责：管理接口级开关状态，决定每个待迁移接口走新前缀还是老前缀
- 存储：Pinia 全局状态（`switchMap` + `lastFetchTime`）
- 拉取：登录后初始化一次；列表页进入按间隔刷新；失败静默兜底

伪代码：
```typescript
defineStore('tmsSwitch', () => {
  const switchMap = ref<Record<string, boolean>>({})   // key → true(走新接口)
  const lastFetchTime = ref(0)                          // 上次拉取尝试时间（不论成败）

  function fetchSwitches() {
    if (fetchingPromise) return fetchingPromise        // 并发去重
    fetchingPromise = (async () => {
      try {
        // 静默请求：路径未上线时 404 不弹错误，由 catch 兜底
        const res = await http.post({ url: SWITCH_API_URL }, { errorMessageMode: NONE })
        switchMap.value = res?.model ?? {}
      } catch {
        // 失败保留旧缓存（isNewEnabled 对未命中 key 返回 false → 走老接口）
      } finally {
        lastFetchTime.value = Date.now()                // 不论成败都记录，避免短时重复
        fetchingPromise = null
      }
    })()
    return fetchingPromise
  }

  const isNewEnabled = (key) => switchMap.value[key] === true   // 兜底：未命中/false → false

  const initSwitches = async () => fetchSwitches()              // 登录后调
  const refreshSwitch = async (force = false) => {              // 列表页调
    if (!force && Date.now() - lastFetchTime < REFRESH_INTERVAL) return
    await fetchSwitches()
  }
})
```

#### 逻辑2：前缀解析器（`api/tms-settlement-prefix.ts`）

- 职责：根据接口级开关，动态返回老前缀 `/lmt-user` 或新前缀 `/tms-settlement`
- key 生成：接口相对路径去首斜杠、去 `lmt-user/` 前缀、剩余斜杠转下划线
- 兜底：开关 false / 拉取失败 / key 未命中 → 返回老前缀

伪代码：
```typescript
function toSwitchKey(relativePath: string): string {
  // /income/costList → income_costList
  // /lscWaybill/page → lscWaybill_page
  // /route-cost-query/cost-apply-list → route-cost-query_cost-apply-list
  let p = relativePath.replace(/^\/+/, '').replace(/^lmt-user\//, '')
  return p.replaceAll('/', '_')
}

function tmsUrl(relativePath: string): string {
  const enabled = useTmsSwitchStore().isNewEnabled(toSwitchKey(relativePath))
  const prefix = enabled ? '/tms-settlement' : '/lmt-user'
  return `${prefix}${relativePath}`
}
```

> `tmsGateway`（GATEWAY 传参模式）保留备用，inTransit 已统一改用 `tmsUrl`。两种模式最终路径等价（见 1.2）。

### 3.2 开关维度设计

采用**接口维度**（每个待迁移接口一个开关 key），非模块维度：

| 维度 | 开关数量 | 灰度粒度 | 选用 |
|------|---------|---------|------|
| 接口维度 | ~52 个 | 最细（单接口灰度） | ✅ |
| 模块维度 | 4 个 | 适中 | ✗ |

- 开关接口一次性返回所有接口的开关状态（`{ key: boolean }` Map）
- key 规则见 3.3
- 可单接口灰度，回滚粒度最细

### 3.3 开关 key 生成规则

key = 接口相对路径去首斜杠、去 `lmt-user/` 前缀、剩余斜杠转下划线：

| 接口路径 | key |
|---------|-----|
| `/lmt-user/income/costList` → 相对 `/income/costList` | `income_costList` |
| `/lscWaybill/page` | `lscWaybill_page` |
| `/lsc-common-statement/status/audit-pass` | `lsc-common-statement_status_audit-pass` |
| `/route-cost-query/cost-apply-list` | `route-cost-query_cost-apply-list` |
| `/payment/batch-transfer` | `payment_batch-transfer` |

> key 不带 `lmt-user` 前缀，仅基于各 API 文件内 url 字段的相对路径生成。

### 3.4 开关缓存与刷新策略

| 时机 | 动作 | 说明 |
|------|------|------|
| 登录完成 | `initSwitches()` 拉取一次 | `main.ts` 用户信息初始化后 |
| 列表页 onMounted | `refreshSwitch()` | 间隔内跳过，超过 `REFRESH_INTERVAL` 才刷新 |
| 业务接口调用 | `isNewEnabled(key)` 读缓存 | 同步，不触发请求 |
| 并发拉取 | `fetchingPromise` 去重 | 避免并发重复请求 |

- `REFRESH_INTERVAL`：刷新间隔（默认 10s，可配置）
- `lastFetchTime`：不论拉取成败都更新，避免失败时短时重复请求

### 3.5 兜底与静默策略

| 场景 | 行为 |
|------|------|
| 开关为 false | `isNewEnabled` 返回 false → 走老前缀 `/lmt-user` |
| 开关接口请求失败/404 | 保留旧缓存（空），`isNewEnabled` 返回 false → 走老接口 |
| key 未命中（switchMap 无该 key） | 返回 false → 走老接口 |
| 开关接口 404 弹错误 | 请求加 `errorMessageMode: NONE` 静默，不弹 toast |

> 核心原则：任何异常情况默认走老接口，保证业务不中断。
