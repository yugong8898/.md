## 二、本次新增功能

### 需求一：C169.6 TMS支持融合网货撮合运单

**1. 客户汇总新增三个多选筛选条件**

- 业务类型：不开票（10）/ 开票（20），下拉多选
- 运单类型：TMS 运单（10）/ 线上运单（20），下拉多选
- 找车类型：公开 / 指定，下拉多选。注意前端映射口径：「公开」查询时展开为 `[10,11,30,40]`，「指定」传 `[20]`

共同口径：

- 默认空选即「全部」，空数组时不向接口传参
- 导出数据与列表筛选口径一致（导出请求同样携带以上字段）

**2. 「查看明细」跳转透传筛选条件**

客户汇总点击「查看明细」跳转运单列表时，当前勾选的四个筛选条件（运单范围 / 业务类型 / 运单类型 / 找车类型）以逗号拼接形式随路由参数透传；未选择的条件不携带。由运单列表侧自行解析消费（跨页面联调项，见第三节）。

**3. 对账单支持运单池 ID（poolId）**

- 新增运单明细提交时（批量新增明细接口），除 waybillIdList 外同步携带 `poolIdList`（选中行的运单池 ID 集合）
- 对账单创建模式提交时，新增 `addPoolIdList`（本次新增明细对应的运单池 ID）、`deletePoolIdList`（与删除的运单明细对应）两个参数

**4. 企业信息认证抽屉样式修复**

el-drawer 存在重复的 `style="padding-bottom: 40px"` 属性，已清理为一处，消除 Vue 编译警告，功能与展示不变。

### 需求二：C187.8 托运人运单支持客户对账

**1. 客户汇总新增「运单范围」筛选**

- 选项：托运人运单（10）/ 承运运单（20），下拉多选
- 位置：「运单对账状态」之后（order 28）
- 默认空选即「全部」，空数组时不传参；导出口径与列表一致

**2. 新增运单弹窗同步增加「运单范围」筛选**

- 弹窗搜索区新增「运单范围」多选下拉，查询时以 `filterModel.bizRoleList` 传入
- 重置按钮、关闭后重新打开均恢复默认空选
- 切换页码时保留筛选条件

**3. 查重口径一致**

客户汇总点击「创建对账单」时，当前「运单范围」随其他筛选参数一并写入 sessionStorage，供对账单页「提交前查重」读取使用，保证查重口径与列表筛选一致（范围外运单不会被误判为重复）。

> 备注：「实际承运」（carrierTypeList）经确认**不需要**，最终实现不含该字段，无需测试。

## 三、后端依赖（测试前确认已部署）

**C169.6：**

- 客户汇总列表接口 `POST /lmt-user/financial-management/customer-summary`：filterModel 支持 `invoiceTypeList`、`tmsFlagList`、`findCarTypeList`（number[]）
- 客户汇总导出接口 `POST /lmt-user/exp/export-data`：同步支持以上三字段
- 批量新增对账明细接口（ltms 服务 `/stmt-detail/batch-create`）：请求体支持 `poolIdList: string[]`
- 对账单创建提交接口（create-v2 / update）：请求体支持 `addPoolIdList`、`deletePoolIdList`
- 联调项：「查看明细」目标运单列表页需能解析路由中逗号拼接的 `bizRoleList` / `invoiceTypeList` / `tmsFlagList` / `findCarTypeList` 参数

**C187.8：**

- 客户汇总列表与导出接口：filterModel 支持 `bizRoleList`（number[]，空即全部）
- 新增运单弹窗列表接口（ltms 服务 `/lscWaybill/page`）：filterModel 支持 `bizRoleList`
- 提交前查重链路使用的运单查询同接口，自动继承上述字段
