## 3. 联调必验项（需后端配合）

以下项目前端代码已实现，但**必须联调时验证后端行为**才能确认闭环：

| 编号 | 验证项 | 前端现状 | 需后端确认 | 对应不确定项 |
|------|--------|---------|-----------|-------------|
| N-01 | 订单详情接口返回 `settlementMode` 字段 | 已按 `1 \| 2` 消费 | 接口是否已在雇主端和服务商端订单详情接口下发该字段 | Q2（已闭环字段名，待联调验证返回值） |
| N-02 | 售后 actions 下发逻辑 | 前端依赖 `apply_after_sale` action 控制入口显隐 | T+1 订单在各阶段是否正确下发/不下发该 action | Q13 |
| N-03 | T+1 订单退款类售后拦截 | 复用现有错误提示机制 | 后端是否对 T+1 订单的退款/部分退款创建请求返回错误码+文案 | R-104 |
| N-04 | 已结算状态下 apply_after_sale action | 前端不做时效判断 | T+1 订单已结算后是否仍下发 apply_after_sale（决定 TC-FE-03 能否进入页面） | 新增 |
| N-05 | remaining 范围 action 独立控制 | 前端强制 canOnlySelectCurrentScope=true | 后端是否对 T+1 订单独立控制 remaining 入口 action | Q13 |

## 5. 前置条件与数据准备

| 条件 | 说明 |
|------|------|
| T+1 订单 | 服务商已打指定标签 + 订单创建时 settlementMode=2 |
| 普通订单 | settlementMode=1 或字段缺失 |
| 验收通过状态 | 订单阶段状态为验收通过（ss=4） |
| 未验收通过状态 | 履约中/待验收/验收不通过（ss≠4） |
| 多阶段订单 | 一付多验或多付多验结构订单 |
| 测试账号 | 需雇主账号 + 服务商账号（provider 角色）各一个 |
