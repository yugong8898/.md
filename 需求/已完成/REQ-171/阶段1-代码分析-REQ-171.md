## 1. 售后申请页现状（核心改动点）

**文件**：`src/views/employer/order/after-sale-apply.vue`（组件名 EmployerAfterSaleDetail）

### 1.1 售后类型枚举

`src/api/common/afterSale/types.ts` L2-L6：

```ts
REFUND_ONLY = 1        // 仅退款
REWORK_ONLY = 2        // 返工
REFUND_AND_REWORK = 3  // 退款+返工
```

注意：PRD 中的"部分退款"对应现状的 `REFUND_AND_REWORK`（退款+返工，申请部分退还款项）；无独立"部分退款"类型。

### 1.2 阶段状态枚举（L378-L387）

`STAGE_STATUS_TAG`：1=待支付、**2=履约中、3=待验收、4=验收通过、5=验收驳回**（PRD 称"验收不通过"）、6=售后中、7=售后完成、8=已关闭。

阶段状态从 URL query 读取（L67-L117）：`stageStatus/stageName/stageNo`，由入口页（订单详情等）跳转时携带。

### 1.3 售后类型选项过滤逻辑（L282-L315，本次核心）

`allAfterSaleOptions`（L284-L295）：三个选项——仅退款（描述按售后范围动态变化）/ 返工 / 退款+返工。

`filteredAfterSaleOptions`（L297-L315）**普通订单现状规则**：

| 条件 | 可选项 |
|---|---|
| 分期验收 + afterSaleScope='remaining'（当前及剩余阶段） | 仅 REFUND_ONLY |
| ss===4（验收通过）且阶段金额≤0 或非数字 | 仅 REWORK_ONLY |
| ss===4（验收通过）且金额>0 | 全部三项 |
| ss∈[2,3,5]（履约中/待验收/验收驳回） | 仅 REFUND_ONLY |
| 其他（如非一次验收且非分期验收模式） | 全部三项 |

`syncAfterSaleType`（L319-L327）：选项变化后自动选中第一个可用项。

⚠️ **关键发现：代码中不存在"无任何选项"分支**。T+1 订单要求 ss∈[2,3,5] 时售后类型为空——需新增"返回空数组"分支，且页面需处理空选项状态（当前页面默认选中逻辑 `afterSaleType=0`，空选项下提交按钮/表单的展示形态需设计）。

### 1.4 售后阶段范围（L120-L136、L347-L352）

`afterSaleScope`：'current'（当前阶段售后）/ 'remaining'（当前及剩余阶段售后），仅分期验收模式（isStagedAcceptMode）使用。

`canOnlySelectCurrentScope`：最后阶段 或 验收通过且阶段金额≤0 时强制 current——**T+1 订单"仅支持当前阶段售后"可复用此强制机制**（新增 T+1 条件即可），且 remaining 描述文案提到"仅支持全额退款"，T+1 下不应出现。

### 1.5 提交链路（L740-L783）

参数类型 `ApplyAfterSaleParams`（`src/api/employer/order/types.ts` L583-L604）：`afterSaleType`、`applyRefundAmount`、`orderStageScopeType`、`orderStageId`、`relatedOrderStageId`、`fulfillmentMode`。提交调用 `applyAfterSale(params)`。T+1 拦截提示依赖后端对此接口返回错误码（前端现有错误提示机制直接复用）。

## 2. 售后入口分布（横向搜索）

| 入口 | 文件 | 控制方式 |
|---|---|---|
| 订单详情-申请售后按钮 | `src/views/employer/order/detail.vue` L1759-L1803 | `deliverablesTargetStage.actions.includes('apply_after_sale')` |
| 订单列表-申请售后 | `src/views/employer/order/list.vue` L295-L310 | `orderHasAction(order, 'afterSales')`，ACTION_LABEL_MAP 映射 |

**结论（解答 Q12）**：两个入口的显隐均由**后端下发的 actions 数组驱动**，前端不做本地状态判断。T+1 订单在无售后类型的阶段（履约中/待验收/验收驳回），后端不下发 action 即可让入口消失，**前端入口逻辑无需改动**；售后申请页内部的选项过滤（1.3 节）为前端本地逻辑，仍需增加 T+1 分支（防 URL 直达时误展示退款选项）。

## 3. 服务商端订单详情页现状

**文件**：`src/views/supplier/order/detail.vue`（L162-L218 template 骨架）

```
顶部：OrderProgressStepper（订单进度条，来自 @/components/order/）
  ↓ 依次渲染卡片：
SupplierOrderTaskCard        服务信息
SupplierOrderPaymentStandardCard  付款金额及交付标准
SupplierOrderPaymentCard      支付信息
SupplierOrderStageProgressCard   阶段验收进度
SupplierOrderContractCard     合同
SupplierOrderSettlementCard   结算
右侧：SupplierOrderSidePanel  雇主信息/价格详情
```

- 数据类型：`SupplierOrderDetailResponse`、`SupplierOrderStage`（`src/api/supplier/order/types.ts`）
- 页面无现成 Alert/横幅组件，顶部提示为**新增 UI**（原型：浅黄背景+信息图标、常驻不可关闭）；Ant Design Vue 的 `a-alert` 可直接使用，需对照原型定样式
- 插入位置：OrderProgressStepper 之上（页面顶部）

## 4. T+1 字段现状

全局搜索 `tPlus / T+1 / specialSettle / settleType / settlementRule / 结算规则 / 特殊结算`：**无业务命中**（仅 SVG 资源与服务发布页 PricingDeliveryCard 的"交付与结算规则"文案，无关）。

**结论**：前端无任何 T+1 订单标识占位，Q2（字段名/接口路径）必须等后端定义；订单详情类型（SupplierOrderDetailResponse / employer order types）中无"订单类型/结算类型"字段。

## 5. 目录结构说明

服务商端由 `supplier/` 与 `provider/` 两目录混用组成：

| 功能 | 目录 |
|---|---|
| 订单管理（本次改动） | `views/supplier/order/` |
| 工作台/任务大厅/保证金/通知 | `views/supplier/` |
| 售后管理（服务商视角，本次不动） | `views/provider/after-sale/` |
| 服务发布/钱包/发票/认证/商机 | `views/provider/` |

雇主端全部在 `views/employer/`。售后申请页 `employer/order/after-sale-apply.vue` 与售后管理列表/详情 `employer/afterSale/` 是不同页面，勿混淆。

## 6. 现状与 T+1 目标规则对照

| 阶段状态 | 普通订单现状（代码实测） | T+1 目标（PRD） | 改动 |
|---|---|---|---|
| 履约中(2) | 仅退款 | **空** | filteredAfterSaleOptions 新增 T+1 空分支；后端不下发入口 action |
| 待验收(3) | 仅退款 | **空** | 同上 |
| 验收通过(4) 金额>0 | 全部三项 | **仅返工** | T+1 分支覆盖金额判断 |
