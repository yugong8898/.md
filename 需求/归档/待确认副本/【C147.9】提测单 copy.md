## 一、需求概述

1. **PC 端调整结算信息页面**：费用明细下方新增「付款方式」模块（预付款 / 到付 / 回单付三个字段固定展示），回单付支持修改，与小计三角联动，保存/提交增加等式校验。
2. **PC 端查看结算信息、司机对账查看**：同步展示付款方式（只读）；隐藏费用明细汇总行、司机对账小计备注里旧的付款方式文字。
3. **移动端（易达宝）**：调整结算/查看结算信息底部增加付款方式模块，逻辑与交互与 PC 端一致；隐藏小计费用备注。
4. **移动端新增 Tab「装卸货磅单」**：展示运单装货/卸货磅单图片，支持放大缩小，无图给占位符。
5. **其他影响**：运单付款时按调整结算信息最新的回单付金额展示；运单原无回单付、调整后改为有值时，不改货源回单付标签。

## 二、重要口径说明

> 以下为开发过程中与需求方逐条确认后的最终口径，与早期需求文档描述不一致处以本节为准。

| 事项 | 最终口径 |
|------|---------|
| 回单付变化导致到付为负 | **保留回单付的值 + 标红错误提示**，不清空（需求文档早期写「清空为 0 / 清空回单付的值」，已确认以 PC 端「保留 + 提醒」交互为准，两端统一） |
| 小计变化导致到付为负 | 到付不更新，展示错误提示，不清空回单付 |
| 回单付比例限制 | 由**输入时动态上限**实现：回单付最大值 = min(小计 × 4PL 配置比例, 999999999.99)，超出即时截断 |
| 磅单展示口径 | 移动端按单张图处理（装货 1 张、卸货 1 张），不做多图网格；图片状态码映射：运输类型 1/2 → 装货 410 / 卸货 430，3/6 → 装货 410 / 卸货 420 |
| 旧逻辑处理 | 所有隐藏/替换的旧 UI 旧逻辑均注释保留，未直接删除 |

## 六、边界和异常用例

| 编号 | 场景描述 | 操作步骤 | 预期结果 |
|-----|---------|---------|---------|
| TC-B01 | 回单付 > 小计导致到付为负 | 小计 1000、预付 200、回单付改 900 | 到付不更新为负数；回单付**保留 900 不清空**；回单付行标红并提示「应付司机运费不等于到付+预付+回单付的值」 |
| TC-B02 | 小计减小导致到付为负 | 小计 1000、到付 100、预付 200、回单付 700，小计改为 700 | 到付不更新；页面出现 ❗ 提示「应付司机运费不等于到付+预付+回单付的值」 |
| TC-B03 | 等式不成立时保存 | TC-B01 状态下点击保存/提交 | 保存被拦截，提示「应付司机运费不等于到付+预付+回单付的值，请修改」 |
| TC-B04 | 回单付超过比例上限 | 4PL 配置比例 50%，小计 1000，回单付输入 600 | 输入被截断为上限 500（小计×50%），无法超出 |
| TC-B05 | 回单付超过系统绝对上限 | 回单付输入超过 999999999.99 的数值 | 截断为 999999999.99 |
| TC-B06 | 回单付输入「5.」后失焦 | 输入框键入 `5.` 然后失焦 | 值归一为 `5.00`，不保留残留小数点 |
| TC-B07 | 回单付清空后失焦 | 删除输入内容后失焦 | 展示 `0.00` |
| TC-B08 | 回单付边界值 0 与 999999999.99 | 分别输入 0 和 999999999.99 保存 | 保存成功，金额展示两位小数无精度丢失 |
| TC-B09 | 浮点精度 | 构造 0.1 + 0.2 类金额组合验证等式校验 | 校验采用 BigNumber 计算并允许 ±0.01 容差，不误判 |
| TC-B10 | 移动端 Tab 切换表单数据不丢失 | 在结算信息 Tab 填写回单付后切到磅单 Tab 再切回 | 回单付等已填数据保留不丢失 |
| TC-B11 | 无磅单图片运单 | 打开无磅单图片运单的「装卸货磅单」Tab | 展示占位符，不报错不白屏 |
| TC-B12 | 磅单接口异常 | 模拟磅单接口返回失败/超时 | 页面兜底展示占位符或空态，不影响结算信息 Tab 使用 |
| TC-B13 | 比例配置接口失败 | 模拟回单付比例配置接口失败 | 回单付上限退回系统绝对上限 999999999.99，其余功能不受影响（容错放行） |
| TC-B14 | 非磅单运输类型 | 运输类型不在 1/2/3/6 的运单查看磅单 Tab | 不发起磅单请求，展示占位符 |
| TC-B15 | 全流程运单 | 打开全流程运单调整页 | 付款方式展示正常，小计取值正确（不取「合计」「全流程应付」等特殊行），联动与保存正常 |

## 八、风险提示

- **风险1**：全流程运单的小计口径需重点验证，避免取到「合计」或「全流程应付」等特殊行导致联动和等式校验异常（TC-B15）。
- **风险2**：运单付款页展示最新回单付依赖后端按最新保存值返回，前端仅展示，若付款页展示旧值需先确认后端数据源（TC-P10）。
- **风险3**：回单付比例限制由输入时动态上限实现，比例配置接口失败时上限退回系统绝对上限，比例限制暂不生效（容错放行设计，TC-B13）。`receiptPayCheck` 保存时二次校验接口两端已封装但本期未启用调用，如产品要求保存时二次拦截需另行评估。
- **风险4**：移动端磅单图片经 OSS 地址转换（H5 转 blob、小程序/APP 转 base64），平台差异大，需在 H5 和微信小程序分别验证图片加载与预览（TC-M03/M04）。
- **风险5**：两端提交金额字段为原始值直传（不做 toFixed），金额精度依赖 BigNumber 归一后的两位小数字符串，建议联调时核对后端入库值（TC-P05）。
