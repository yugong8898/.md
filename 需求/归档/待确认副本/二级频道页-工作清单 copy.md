## 1. 需求概述与工作范围

**需求背景**：运营后台（`ai-platform/es-ops-platform`）新建二级频道配置体系，配置页含 11 个模块，按 `module-registry` 三件套（`index.vue` / `validate.ts` / `submit.ts`）逐个实现。完整后台落地见同目录《二级频道页-运营后台落地文档》。

**本清单工作范围（我负责）**：内容运营相关的 3 个模块——

1. **智能体市场**（`agent-market`）
2. **活动专区**（`activity-zone`）
3. **行业资讯**（`industry-news`）

每个模块交付五件套：**`index.vue`（表单编辑态）、`types.ts`（数据结构）、`validate.ts`（模块校验）、`submit.ts`（模块提交 payload）、`readonly.vue`（详情只读展示）**。

### 团队分工（已确认）

| 负责人 | 范围 |
|---|---|
| 梁树强 | 频道管理主链路：菜单/路由/权限、二级频道列表（筛选/状态展示/查看线上配置/查看进度/编辑/下线/重新发布）、审核列表、线上配置详情页/变更进度详情页/审核详情页框架、初审/复审弹窗、公共 API（列表/详情/审核/下线/发布接口）与公共状态枚举 |

### 统一协作规则（已确认）

1. 每个模块固定交付：`index.vue`、`types.ts`、`validate.ts`、`submit.ts`、`readonly.vue`；
2. 模块校验只写在自己的 `validate.ts`；
3. 模块提交结构只写在自己的 `submit.ts`；
4. 详情页只消费各模块 `readonly.vue`；
5. 公共 API、公共状态、路由权限由梁树强统一维护；
6. 大表单外壳、模块注册、总校验、总提交由张立统一维护。

### 核心前提（实读代码确认）

- 三个模块骨架已存在，当前均为占位：`index.vue` 为 `el-empty`，`validate.ts` 恒返回 `valid: true`，`submit.ts` 使用 `createEmptyModulePayload` 透传。
- 注册机制已就绪：`form/module-registry.ts` 已登记三模块的 `component / validate / buildPayload`；`form/index.vue` 提交时按注册顺序逐模块校验，失败自动定位到对应模块并 `ElMessage.warning` 提示。**实现时沿用该机制，不绕开。**
- 接口层全 mock（`src/api/secondary-channel/index.ts`），本次开发先按约定数据结构对接，真实接口切换时只改接口封装层。
- 详情只读展示的消费方（线上配置详情页 / 变更进度详情页 / 审核详情页，含初审/复审弹窗）由梁树强开发，统一消费各模块 `readonly.vue`；本轮按协作规则交付只读组件。

## 3. 二、模块通用业务规则

### 3.1 三模块同构部分

| 规则项 | 说明 |
|---|---|
| 启用/禁用开关 | 控制模块是否在前台展示；**禁用不删除已配置数据**，重新启用可继续使用 |
| 前台展示名称 | 模块启用时**必填**；用于前台模块标题（如"智能体市场""企业智能助手"） |
| 查看更多开关 | 开启时可填跳转链接；关闭后前台不展示入口，**已填链接保留** |
| 跳转链接 | 需符合标准网址格式校验；前台统一新窗口打开；禁止危险脚本链接 |

### 3.2 图片规则（三模块统一）

- 仅支持 PNG / JPG / JPEG，单张 ≤ 20MB；
- 上传成功后展示图片预览；
- 未配置图片或加载失败时，前台展示缺省状态（后台编辑态展示占位）。

### 3.3 模块校验与提交机制（对齐既有骨架）

- `validate.ts`：导出 `validateModule(formData: SecondaryChannelFormData): Promise<ModuleValidateResult>`；校验失败返回 `{ valid: false, message }`，由 `form/index.vue` 统一提示并定位模块。**保存草稿不触发校验，提交审核才校验。**
- `submit.ts`：导出 `buildModulePayload(formData): SecondaryChannelModulePayload`，返回 `{ moduleKey, data }`；`moduleKey` 与 `module-registry.ts` 中的 `key` 一致（`agent-market` / `activity-zone` / `industry-news`）。
- 各模块数据统一挂在 `formData.modules[moduleKey]` 下。
- **数据结构先行**：先在 `types.ts` 定结构并按此开发，真实接口字段确认后集中替换（不在组件内散落硬编码字段）。

### 3.4 详情只读展示要求（方案已定稿：独立 `readonly.vue`）

- 每个模块新建 `readonly.vue`，与 `index.vue` 平级，消费同一份 `types.ts` 数据结构；
- 只读态展示内容与编辑态配置一一对应：已配置图片可预览，已配置链接可点击并新窗口打开；
- 消费方为梁树强开发的详情页（线上配置详情页 / 变更进度详情页 / 审核详情页，含初审/复审弹窗），本模块不感知消费方细节；
- `readonly.vue` 的入参契约（直接收模块 `data` or 从 `formData` 取）开发前与梁树强、张立对齐一次（见待确认 #12）。

## 8. 七、接口和字段说明

### 8.1 公共接口（梁树强统一维护，本清单只消费）

| 接口 | 用途 |
|---|---|
| 列表接口 | 频道列表 / 审核列表 |
| 详情接口 | 编辑态回显 / 详情页只读数据（三模块 `index.vue` 回显与 `readonly.vue` 渲染的数据来源） |
| 审核接口 / 下线接口 / 发布接口 | 主链路操作 |

### 8.2 模块专属检索/上传接口（归属待确认 #13，真实接口均待后端，先 mock）

| 接口 | 用途 | 使用模块 |
|---|---|---|

### 8.3 字段约定原则

- 当前按各模块 `types.ts` 中的占位字段开发，组件内不出现真实接口字段硬编码；
- 接口契约确认后，只改 `src/api/secondary-channel/` 封装层做字段映射，组件不动；
- `submit.ts` 输出的 `data` 结构即为提交契约的前端侧定义，需与后端对齐一次。

## 11. 十、开发顺序建议

1. **公共件先行**：模块表头组件、查看更多组件、图片上传封装、链接校验工具（三模块共同依赖）；
2. **行业资讯**：结构最简单（单弹窗 + 列表），用于打通「表单 → 校验 → payload → 只读态」全链路；
3. **智能体市场**：复用行业资讯模式，增加封面图选填与启用状态；
4. **活动专区**：复杂度最高（双选择弹窗 + 开关联动 + 拖拽排序），放最后；
5. 待确认 #1 #2 #3 有结论后，回头收敛活动专区校验口径；
6. 接口契约确认后统一替换封装层，走一遍第 10 节回归。

## 12. 十一、风险点

| 风险 | 说明 | 规避方式 |
|---|---|---|
| 活动 Banner 数量口径未锁定 | 3 vs 不限，影响上限校验 | 先按 3 实现 + `TODO: wxj`，确认后一处修改 |
| 数据结构先行可能与后端契约偏差 | 联调时字段大面积返工 | 联调前与后端对一次 `submit.ts` 的 `data` 结构（待确认 #11） |
| 详情回显契约未定 | 编辑态回显依赖框架侧接口，可能阻塞联调 | 编辑态先以本地 `formData` 为准开发，回显接口就绪后接 |
| 只读态消费方页面未建 | 只读态无法独立验收 | 先在模块内自测只读渲染，消费方接入时回归 |
| 拖拽排序依赖库选型 | 项目未确认拖拽方案 | 开发前确认项目已有拖拽依赖（如无则提评审） |
| 活动数据实时性 | 已选活动在审核期间可能过期 | 前台失效隐藏由前台处理；后台展示活动状态以检索时为准 |
| mock 缓存陷阱 | `api/secondary-channel` 模块级内存缓存，刷新丢失 | 不在 mock 行为上建立测试结论，联调切真实接口后重测 |
| 协作边界越界 | 误改 `form/index.vue`、`module-registry.ts`、公共 API 引发与张立/梁树强的合并冲突 | 严守 2.3 边界；注册表与公共层改动先对齐再动手 |
| `readonly.vue` 契约未对齐 | 详情页接入时入参不匹配返工 | 开发 `readonly.vue` 前先与梁树强定入参契约（待确认 #12） |
| 检索接口归属悬空 | 活动专区弹窗无数据源阻塞开发 | 优先推动待确认 #13，未定前先用 mock 函数占位 |
