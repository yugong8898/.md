# 二级频道编码与 SLUG 职责调整建议

建议补充一轮需求迭代：为二级频道明确稳定的内部编码，技术内部通过编码识别频道；SLUG 按产品的渠道区分诉求重新定义，并补齐已有链接的兼容规则。

这次沟通希望先把两边对 SLUG 的理解对齐，再确定页面配置、接口和历史链接如何调整。

## 为什么需要这次调整

需求初期，这个值承担的是识别二级频道的作用，原本可以使用频道 ID。考虑到 ID 放在公开网址里不直观，后来使用更容易理解的 SLUG，例如工商财税的 `gscs`。

现在产品把 SLUG 理解为区分渠道的值，而技术实际通过它查找频道页面。例如访问 `/gscs`，前台会将 `gscs` 放进频道查询接口。后台又允许运营修改 SLUG，这就把渠道配置和频道识别连在了一起。

这里需要补齐的是字段职责和修改后的行为。运营调整一个渠道值时，应当能明确知道是否会影响已经发出的链接。

## 目前有什么影响

| 场景 | 对业务的影响 |
|---|---|
| 运营修改 SLUG | 如果旧路径没有保留映射，广告、二维码和历史分享链接可能找不到原频道。 |
| 同一个频道投放多个渠道 | 需要说明多个渠道如何对应同一频道，否则容易把渠道配置变成新建或改名频道。 |
| 页面持续更新 | 业务希望更新内容后继续使用原物料，需要一个稳定的频道标识维持关联。 |
| 工商财税使用专属域名 | 需同时确认域名下可展示哪些频道，以及旧链接如何到达新地址。 |

目前无匹配频道且接口返回空对象时，前台会跳到主站首页。因此即使链接仍能打开，访客也可能看不到投放时承诺的内容。旧物料是否失效，应以它还能否到达正确频道判断。

## 建议怎样调整

| 内容 | 建议职责与操作规则 |
|---|---|
| 二级频道内部编码 | 创建频道时由系统生成，作为技术内部流转和查询的稳定标识。运营可查看或复制，普通页面编辑不修改。 |
| 现有频道 ID | 保留原有数据关系。研发先核对现有 ID 能否满足稳定编码的要求；如果确需增加编码，明确 ID 与编码的对应关系及唯一规则。 |
| SLUG | 按产品确认的渠道含义配置，渠道记录关联内部频道编码。需要多个渠道时可关联同一个频道。是否继续作为网址路径，由产品结合现有投放方式确认。 |
| 页面名称 | 用于后台识别及业务展示，按需求编辑。改名时保持频道编码及已有渠道关联稳定。 |
| 公开链接 | 通过访问地址找到渠道或历史路径，再定位对应频道编码。技术内部后续使用该编码查询页面。 |

例如，工商财税频道有一个稳定编码 A。业务创建渠道甲、渠道乙，两条渠道记录都关联 A，访客通过各自的链接进入同一个工商财税页面。修改页面标题、Banner 或其他内容时，渠道关联继续有效。

渠道使用哪种值、是否需要跟踪访问来源，需要产品明确。若只是区分渠道，可以先定义渠道记录和关联规则；访问统计作为需要单独确认的需求范围。

## 历史页面和物料怎么过渡

1. **核对已有频道。** 为每条记录确认内部编码，整理当前域名、SLUG 和已知投放链接。已有 `gscs` 等值作为历史访问入口保留关联。
2. **先建立映射，再切换查询。** 新旧入口都能找到同一个频道后，技术内部切换到编码查询。迁移期间核对旧页面内容和访问权限。
3. **约定改址行为。** 新增渠道可生成新入口。更改或停用旧入口前，后台给出影响提示，并明确保留访问、跳转或停止服务的处理方式。
4. **验证工商财税入口。** 已确认地址为 `https://cs.wdsheng.com/gscs`，cs 域名只展示工商财税。旧 `channel.wdsheng.com/gscs` 如何过渡，需要产品和技术一起确认，并验证链接携带的渠道参数。
5. **同步搜索配置。** 静态预置的页面标题、描述、关键词以及页面的标准网址，跟随实际对外地址一起核对。

## 需要产品补充的需求

建议在迭代需求中明确以下五项：

1. **内部编码的职责。** 确认系统生成、保持稳定，以及后台是否需要展示。研发核对复用现有 ID 或新增编码的具体方式。
2. **渠道的定义。** SLUG 区分的渠道具体指什么，一个频道能否对应多个渠道，渠道能否修改、停用或重新分配。
3. **渠道的配置入口。** 是否从频道编辑中管理渠道，谁可以配置，是否需要审核，以及界面如何提示已经投放的地址。
4. **旧链接的兼容规则。** 改渠道值、停用渠道或换域名后，原物料应到达哪里，哪些操作需要业务明确确认。
5. **本轮交付边界。** 频道编码、渠道与频道关联、旧链接兼容纳入本轮评审；渠道访问统计是否需要一并提出。

此前讨论的 SLUG 下拉，可以作为渠道选项配置的一种交互方式。最终选项和修改规则需要以本轮明确的渠道定义为依据。

## 验收怎么判断

- 修改页面名称或内容后，原二维码和投放链接仍能进入对应频道。
- 同一个频道配置多个渠道时，各入口都能找到同一条频道记录。
- 修改或停用渠道时，后台提示及旧链接行为符合已确认规则。
- 历史 SLUG 和新编码能定位同一个频道，迁移过程保留原数据关联。
- `cs.wdsheng.com` 下的访问始终满足工商财税的内容隔离要求。
- 异常路径、旧链接跳转及页面搜索信息都经过验证。
