## 现状架构要点

1. **工作台双版本模型**：`CategoryChannelWorkbenchDTO` 含 `published_version` / `progress_version`，编辑回显优先 progress、兜底 published（`config-mapper.ts` `hydrateFromWorkbench`）。列表、进度、审核详情、线上各读各的接口版本——Q-03 类版本时点问题由服务端数据驱动，前端只渲染。
2. **模块单例注册表**：`module-registry.ts` 固定注册 12 模块，每 key 一份数据存于 `formData.modules[key]`；左侧导航顺序 = 注册表数组顺序；`seo` 在 `SECONDARY_CHANNEL_HIDDEN_MODULE_KEYS` 中隐藏。**无模块实例、无动态排序、无增删能力**——本次多 Banner/多智能体市场与排序是结构性扩展。
3. **模块五件套规范**：`index.vue / types.ts / validate.ts / submit.ts / readonly.vue`；数据读写必须走 `useSecondaryChannelFormContext` 的 `getModuleData/setModuleData`，禁止模块内独立状态；提交审核跑全量 `validateModules`，保存草稿不跑。
4. **表单外壳**：`form/index.vue`（714 行）负责 init 建档（`initSecondaryChannelDraft` 按 channelId 或 categoryId）、保存、提交、后端 `field_violations` 定位到模块。新建频道进页即 init 拿 channel_id 补写 URL。
5. **前台固定顺序渲染**：`sub-channel/index.vue` 模板硬编码区块顺序（顶部轮播 → 快捷入口 → 智能市场 → 活动 → 最新 → 推荐 → 行业资讯 → 底部 Banner → 页脚），每类区块单实例；数据来自 `GET /v1/employer/category-channels/{slug}`（路由守卫预取 + `useSubChannelData` 消费），空配置跳回主站。
6. **共用头部组件**：`ModuleHeader.vue` 已支持 `v-model:enabled` 启停开关（关闭仅控前台展示、配置保留）与 `v-model:display-title` 前台展示名称——R-003 开关与 R-004 前台名称独立可直接复用；后台名称编辑入口需新增。
7. **拖拽能力已有**：`form/composables/useDragSort.ts` 已在 agent-market 卡片排序使用，模块级排序可复用。

## TDK 静态预置机制链路

已实读验证的完整链路（R-008 实施基础）：

```
build/seo-tdk.mjs（SEO_STATIC_PAGES 单一数据源，现仅 categoryId=4/9）
  ├─ 构建期：build/seo-prerender.mjs 在 vite build 后替换 dist/index.html 的 head TDK
  │          → 产出 dist/seo/categoryId-{id}.html，nginx 按 query 内部 rewrite（运维配置）
  └─ 运行时：src/config/seoStaticTdk.ts 导入同一 .mjs（类型 seo-tdk.d.mts）
             → sub-channel/index.vue watch 中 getSeoStaticTdk(route.query.categoryId)
             → 命中：静态 TDK 覆盖接口 seo + 动态 canonical；未命中：seo.title || categoryName
```

- 新增预置 = 向 `SEO_STATIC_PAGES` 追加条目，构建期与运行时自动同步，无两套文案漂移。
- **独立页匹配键待定**：现机制按 `categoryId` query 命中；独立页无类目，需与 server/运维确认寻址方式（slug 或新 query 键）后扩展匹配规则——列入契约对齐项，未确认前不落地推测实现。
- 静态页生成已在临时目录用项目 HTML 模板验证过 TDK 逐项替换正确（见 workflow-state 验证记录）。

## 风险与注意事项

- **结构性扩展是最大风险**：模块单例 → 多实例 + 动态排序触及注册表、formData 结构、build/hydrate 双向映射、详情回显全链路；旧类目频道数据必须原样回显与提交（基线复制机制 `build-api-config.ts` 是兼容抓手）。
- **前台模板重写范围**：固定顺序改数据驱动顺序时，顶部轮播压底（-124px 重叠）、快捷入口、断网/骨架/空配置跳主站等既有行为须保留。
- **图片裁切区分**：新 Banner「高度不限不裁切」与存量底部 Banner 固定裁切是两套规则，勿误改旧模块。
- **协作边界**（知识库规范）：外壳不写模块业务校验、模块只改自己目录、数据读写走 context——实例化方案须在该约束内设计。
- **知识库滞后**：kb 模块卡仍写 11 模块，本文以代码 12 模块为准；回写 kb 待用户确认。
- **审核中锁定**：`fieldsLocked`/`isAuditing` 逻辑覆盖新增的实例操作（排序/删除/改名在审核中同样禁用）。
