## 数据与渲染

1. 在频道模块下建立纯数据适配文件，将旧单例和新增统一数组转换为同一份可展示列表。列表项包括稳定标识、模块类型、权重及原有业务数据。新增 Banner 和 Agent 业务结构沿用已有类型。
2. 权重暂沿用后台临时字段 `sort_weight`，升序排列。字段名、类型和层级最终由接口确认，集中在适配层切换。
3. 每个旧模块保留原默认位置。未提供有效权重时采用默认位置，权重相同按原输入顺序稳定排列。后端仅部分模块返回权重时可能与缺省位置冲突，联调需确认完整权重或缺省规则。
4. 底部配置单独渲染。对模块显式返回的禁用状态进行过滤，历史字段缺省按原展示逻辑处理。过滤没有可展示内容的模块，避免空白占位。
5. 新增实例使用后端稳定 ID，本地演示可使用本地生成 ID。真实接口缺少 ID 时需确认，避免以重复标题或排序位置作为实例身份。
6. 后台识别名称仅用于后台，前台继续使用原业务数据中的展示标题。草稿变化通过已有审核发布链路生效，前台读取生效版本。

## 布局和组件复用

新增 Banner 使用静态 Banner 组件，宽度随内容区变化，高度按原图比例展示。各 Agent 继续复用智能体市场区块，每块单独传入内容、展示标题和更多链接。

顶部轮播当前全宽且固定高度，其他模块在居中内容区。建议每个排序项使用统一外层位置，普通模块套居中容器，轮播保留全宽容器，使轮播在中间时仍可展示完整宽度。此布局为实施建议，需产品或设计确认。顶部轮播移动后还要重验背景、边距、分页器和加载骨架。

需求留言当前放在 Footer 内。后台已将留言列为可排序展示模块，建议提取原留言区块独立复用，底部信息继续固定。实现前核对留言提交、来源类目及登录行为，避免搬移后丢失参数。

模块仅在实际展示时占用垂直间距。检查相邻 Banner、连续 Agent、全部禁用和仅剩底部的页面。沿用频道现有最小宽度和窄屏策略，QA 提及的 App、小程序入口需确认是否使用相同 H5 页面。

## 独立页与访问

独立页只展示图片模式类目，隐藏最新服务产品，类目列表及推荐产品尊重启停。独立页没有一级类目时，核对图片跳转、搜索、更多链接、服务入口和留言参数，避免生成包含 undefined 的地址。活动数据来源待接口对齐。

已确认工商财税访问 `https://cs.wdsheng.com/gscs`，两个域名内容隔离。前端域名检查配合入口或接口的频道归属校验。跨域 SLUG、无 SLUG、无匹配频道和接口失败分别验证，异常响应与旧链接跳转策略待对齐。

TDK 按静态预置处理。当前构建和运行时按 categoryId 匹配，而新地址确认仅有 /gscs，需检查域名与路径匹配及 Nginx 首屏返回。不能依赖链接始终携带 categoryId。产品提供文案后同步校验构建 HTML 和浏览器标题。
