## 项目概况

- **需求编号**：REQ-132（云效 RZMP-9033）
- **需求名称**：服务商工作台展示订单/售后动态（含重要商机推荐）
- **所属平台**：企服线 `ai-platform/es-web`（服务商端 PC）
- **技术栈**：Vue 3 + TypeScript + Vite 6 + Ant Design Vue 4 + Pinia 2
- **范围收口**：本期仅交付 Web 端，App 端由其他开发人员负责
- **产品经理**：傅杰彬

## 核心文件说明

### 编排层
- **`index.vue`**（403 行）：WelcomeSection 全宽置顶 → main-content 分左右两列。left-column(flex:1) 依次放 MetricCards、OpportunityRecommendModule、dynamic-row(OrderDynamic|AfterSale)；right-column(固定宽度 368px) 纵向放 ActionCenter 与 SupplierCtaCard。左列三模块被 `v-if="certified"` 包裹，未认证时显示 CertificationPlaceholder。数据拉取由各组件自治，`onMounted` 仅处理埋点、路由参数清理与新手引导链路。
- **`FORCE_SHOW_PROVIDER_GUIDE`**（第 89 行）：开发调试用临时开关，当前值为 `false`。控制新手引导是否跳过正常判定强制弹出。联调完成后应删除该常量及相关引用（共 4 处）。

### 状态管理
- **`stores/provider/dashboard.ts`**：`certified` computed 是认证状态单一来源（底层依赖 `userStore.isProviderCertified`）；`fetchStatistics` 由 MetricCards 调用，内置主体切换竞态防护（statisticsRequestVersion + providerId 双重校验）
- **`useSupplierCtaCard.ts`**：供应商卡片全部业务逻辑（认证判断、supplierStatus 接口、曝光埋点、资源预加载、主体切换监听、三个点击处理函数）
- **`useDynamicModule.ts`**（92 行）：泛型中间层，封装 fetchFn + 5 分钟轮询（DEFAULT_POLLING_INTERVAL = 5 * 60 * 1e3）+ onUnmounted 清除 + 四态渲染。使用顶部 `import type { Ref }` 替代内联类型。

### 共享资源
- **`CertificationBanner.vue`**：`CERTIFICATION_BANNER_URL` 唯一定义点（定义在组件内，无独立 constants.ts）；CertificationPlaceholder 直接渲染，WelcomeSection 以 `hidden` 模式挂载后调用 `openPreview()`。统一封装 `<a-image>` + 受控 preview，props: `hidden`（隐藏模式供外部触发）、`preview`（动态控制是否启用预览）；expose: `openPreview()`

### 订单详情页锚点能力
- **`src/views/provider/order/detail.vue`**：新增 `scrollToHash` 函数（使用 `getBoundingClientRect` 计算相对位置）+ `id="bond"` / `id="deliverable"` 锚点 + `watch(route.hash)` 同页面 hash 变化补滚。OrderListItem.vue 跳转已带 hash（`#bond` / `#deliverable`）。

### 样式规范
- 所有 `.less` 文件遵循 SCSS 嵌套规则：BEM 子类必须嵌套在父块内（`&__child`），禁止平铺
- 共享样式通过 `@import './styles.less'` 引入，各组件自有样式写在 `<style scoped>` 内

## 关键设计决策

1. **接口无关中间层**：`useDynamicModule<T>` 泛型封装，后端契约确定后只替换 fetchFn，组件层零改动
2. **组件数据自治**：纯展示型（WelcomeSection）数据经 props 传入；自治型组件（MetricCards/ActionCenter/SupplierCtaCard）直接读 store 且自行拉取（挂载自拉 + watch 主体切换重拉），跨页面流程的动作（如成为服务商申请）经 emit 上抛编排层
3. **图片资源单点定义**：同一资源多处展示时，URL 收敛到共享组件内单点定义（如 `CertificationBanner.vue` 的 `CERTIFICATION_BANNER_URL`），禁止重复副本
4. **认证状态单一来源**：任何"认证前/认证后"分支都读 `store.certified`，不在组件里重新推导
5. **先骨架后契约**：阶段3 两段式开发，mock 先行，避免被后端契约阻塞
6. **文件夹包裹 + 状态组件独立**：动态模块和 SupplierCtaCard 均采用文件夹结构，loading/error/empty 各自独立为组件
7. **锚点滚动能力**：订单详情页新增 `scrollToHash` 能力，支持从工作台跳转后锚定到保证金/交付物区域（R-007）

## 已知坑点与注意事项

1. **Ant Design Vue Image preview**：不是可调用方法，只能通过 `:preview="{ visible, onVisibleChange }"` 受控；CertificationBanner 用 expose 包装 openPreview 供外部调用
2. **Vite 目录解析**：import 路径省略到目录名时 Vite 运行时能解析 index.vue，但 vue-tsc 会报 TS2307，必须显式写到 `/index.vue`
3. **supplierStatus loading 陷阱**：未认证用户的 supplierStatus 为 null，loading 条件必须加 `certified &&` 前置，否则永远卡在 loading 占位
4. **事件名 camelCase**：ESLint `vue/custom-event-name-casing` 要求自定义事件用 camelCase，kebab-case 会告警
5. **样式嵌套**：SCSS/Less 子元素样式必须嵌套在父元素内，禁止平铺为独立选择器
6. **mock 调试残留**：三个模块的 mock fetchFn 各含 1 条 `console.log`（共 3 处），联调替换真实接口时随 mock 整体删除；若第一批先提交，提交前需清除
7. **index.vue.bak 已入暂存区**：1701 行原始备份文件已被 `git add`，提交前需决策是否入库（建议移出暂存保留本地追溯，或加 ignore 规则）
8. **`scrollToHash` 滚动容器查找**：使用 `findScrollContainer` 工具函数向上遍历 DOM 树查找 `overflow-y: auto/scroll/overlay` 且 `scrollHeight > clientHeight` 的容器；`.order-detail-page` 自身是滚动容器（`overflow-y: auto` + `hide-scrollbar-y()` mixin）
9. **`getBoundingClientRect` vs `offsetTop`**：计算锚点滚动位置时，`getBoundingClientRect` 不依赖 `offsetParent` 链，更可靠
