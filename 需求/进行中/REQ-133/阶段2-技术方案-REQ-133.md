## 3. APP 唤起实现参考

参考文件：`/Users/limengxiao/workspace/bondee/spatio-clotho-h5/src/view/utils/invokeApp.js`。

参考实现流程是：跳转自定义 scheme → 设置约 2.5 秒定时器 → 监听页面 `visibilitychange`；页面进入 hidden 时清理回退计时并视为唤起成功，超时仍未切走则执行商店回退。页面重新 visible 且计时器仍有效时视为唤起失败并回调。

本需求只借鉴“scheme 尝试 + 页面可见性判断 + 延迟商店回退”的交互机制，不复用 Bondee 的 scheme、JSON deep link、平台探测工具或商店地址。实现时使用已确认的 `wdsheng://open/<encoded-path>` 和本需求提供的 iOS/Android 商店 URL。

建议封装为 miniapp 内可复用的 `invokeApp` 工具，顶部组件负责展示和点击；工具输入目标 path、平台回退地址和可选成功/失败回调。重复触发前清理旧 timer；离开页面/组件卸载时清理 timer 和 visibility listener，避免晚到回退或监听器泄漏。超时初始值可按参考设为 2500ms，但应由真机验收调整。H5 环境专用，weapp 不注册该可见性唤起逻辑。

## 5. APP 唤起流程

1. 顶部按钮点击后取得当前页面对应的 path；path 的来源/构造规则需 U-006 确认。
2. 对 path 执行一次 URL encode，组合为 `wdsheng://open/${encodedPath}`。需验证 encode 边界，避免双重编码或把完整 URL 错当 path。
3. 清理已有 timer/listener，记录本次尝试并令浏览器跳转至 scheme。
4. 监听 `visibilitychange`：进入 `hidden` 表示已切入 APP，清理 timer/listener；在超时前返回 `visible` 表示唤起失败，按约定回退商店。
5. 超时仍未切入 APP，按 Android/iOS 平台跳转到对应商店链接。
6. 回退 timer、事件监听器须可清理；重复点击只保留一次有效尝试。

失败识别在浏览器中属于启发式判断（页面可见性/超时），不能证明设备一定未安装 APP；需在 iOS Safari、Android Chrome、微信内置浏览器及 APP WebView 实机验证回退行为。

## 12. 频道页登录门禁与端分流（R8 补充，2026-11-26，批次30~34 设计依据回填）

### 12.1 登录门禁矩阵（用户两轮收窄裁决后的终态口径）

| 点击/交互点 | 门禁 | 实现 |
|---|---|---|
| banner（top/bottom） | 有 | `handleGatedSelect` → `requireLoginForCurrentPage` |
| 类目 STANDARD | 有 | `handleSelectCategory` 内置门禁 |
| 类目 IMAGE 图片卡 | 有 | `handleGatedSelect` |
| 留资控件聚焦（4 input + 1 textarea）/ picker / 提交 | 有 | `@focus` / `handlePickerTap` / `onSubmit` 前置；服务端 `openLoginDialog` 兜底保留（双保险） |
| 服务卡 / 资讯 / 智能体 / 查看更多 | 无 | `handleSelectProduct` / `handleSelectLink` 直跳 |

登录后回频道页不续跳原目标（returnTo 机制，设计流程图口径）；未登录聚焦键盘可能瞬现再随跳页收起（已知行为）。

### 12.2 公共门禁函数与端分流

- `router.ts` `requireLoginForCurrentPage()`：同步门禁，已登录 true；未登录调 `openLoginForCurrentPage()` 并返回 false，不等待登录结果（与 `promptLogin` 异步等待语义区分）。index.vue / ChannelInquiry 两处副本已收敛单点。
- `openLoginForCurrentPage()` 端分流（用户裁决「APP内要调用APP的登陆 端不同处理逻辑肯定不同」）：`isAppWebview()` → `openNativeLogin()`（桥特性检测 + try/catch，失败降级 H5 登录页）；纯浏览器 H5/weapp 维持站内登录页。133 门禁与服务端兜底链均走此函数，单点全生效。
- `utils/app-bridge.ts`：桥接口 + `getAppBridge` 共享单点（jump.ts 服务详情原生分支同源复用）；`openNativeLogin` path 占位 `wdsheng://open/es/auth/login`（`TODO: wxj` U-020）。

### 12.3 已知缺口与后续改造项

- **容器登录态识别（U-013 实现缺口）**：miniapp H5 只认自有 `authSession`，不消费容器注入的 Cookie/localStorage 登录态——APP 已登录用户被误判游客。后续改造：监听 `flutterMessage` 的 `pageReady` → 用注入态调用户信息接口校验后建 session；落地前原生登录完成回 H5 仍判游客（中间态，替换条件已写 app-bridge 注释）。
- **外链策略（批次30）**：白名单移除，任意 http(s) URL 进 webview；APP 容器 Cookie 只注入 `*.wdsheng.com`，随机外链不带登录态（运营责任）。
