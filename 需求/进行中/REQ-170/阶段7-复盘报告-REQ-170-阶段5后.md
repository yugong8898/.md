## 暴露的问题

### P1：KeepAlive 内注释导致编译阻塞（交付后发现）

**问题描述**：阶段3首次交付后，用户反馈 Vite 报错 `<KeepAlive> expects exactly one child component.`。根因是 REQ-170 新增注释放在 `keep-alive` 内部，保留注释编译时注释与动态组件构成两个子节点。

**根因**：回归脚本对布局去注释后检查 key 表达式，未覆盖 `compilerOptions: { comments: true }` 的完整布局模板编译。ESLint、类型检查及结构断言均不足以发现此错误。

**影响**：交付后编译阻塞，开发服务无法启动；首次 CodeReview 漏检。

**改进措施**：已在回归脚本中补充 `test('布局模板保留注释时可编译，KeepAlive 保持单子节点')` 断言（L509-520），后续涉及 KeepAlive 区域的改动必须包含保留注释的完整模板编译验证。

### P2：弹窗回调初版遗漏 DOM 可见性重置

**问题描述**：onModeSwitchTipConfirm 初版仅重置 `signBeforePay=false`，未同步设置 `canChangeOrderType=false`，导致弹窗关闭后 checkbox DOM 仍然可见。用户指出"勾选的dom结构需要一并处理掉"。

**根因**：只考虑了数据状态归位，未同步考虑 UI 可见性。UI 状态重置应同时处理：①数据状态归位 ②DOM 可见性同步 ③是否需要刷新。

**影响**：回调行为不完整，需用户提醒才补全。

**改进措施**：建立 UI 状态重置三要素检查清单（数据状态 + DOM 可见性 + 刷新必要性），后续涉及状态重置的回调必须逐项核对。已沉淀为记忆。

### P3：过度预留 TODO 注释

**问题描述**：onModeSwitchTipConfirm 上方曾标注 `// TODO: wxj 当前仅关闭弹窗+隐藏勾选模块；后续可能改为整页重载或路由replace`。用户要求"看下现有的代码实现即可"，确认当前实现已满足需求后移除。

**根因**：习惯性为未来可能性预留 TODO，但现有实现已完备，TODO 反而误导维护者认为当前实现不完整。

**影响**：增加维护者的不确定性。

**改进措施**：TODO 只标注真正未完成或待外部确认的事项；现有实现已满足需求时不预留"未来可能"型 TODO。

### P4：ESLint 初次校验假通过

**问题描述**：阶段3首次 ESLint `--quiet` 返回 exit=0，实际忽略了目标文件（es-web 的 eslint.config.js 配置了 ignorePatterns）。改用 `ignore:false` 强制校验后发现 3 条历史 warning。

**根因**：未验证 ESLint 是否实际扫描了目标文件，将"无输出"等同于"通过"。

**影响**：验证证据无效，需返工重跑。

**改进措施**：ESLint 校验必须确认文件未被忽略；企服线使用 flat config，不加 `--no-eslintrc -c` 旧 flags。已沉淀为记忆 "ESLint忽略规则与存量类型错误造成的校验假通过陷阱"。

### P5：FriendlyTipModal 扩展后被替换

**问题描述**：为 REQ-170 扩展了 FriendlyTipModal（新增 buttonText prop + @confirm emit），但后续评估确认 ConfirmActionModal 更适合，切换后 FriendlyTipModal 的扩展仍保留（purchaseTipOpen 实例继续使用）。

**根因**：初次选型未充分对比项目已有组件能力，导致先扩展再替换。

**影响**：FriendlyTipModal 的扩展代码成为冗余（虽不影响功能）。

**改进措施**：新增弹窗前先对比 ConfirmActionModal vs FriendlyTipModal 的能力矩阵；ConfirmActionModal 是 FriendlyTipModal 的功能超集，错误/警告/双按钮场景优先选用前者。已沉淀为记忆。
