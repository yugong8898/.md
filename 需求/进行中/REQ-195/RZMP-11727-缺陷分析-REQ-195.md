## 二、已确认产品口径（2026-11-20）

新用户认证流程中，CA 认证（授权委托书）审核失败后的交互口径已由需求方确认：

1. **正常流程**：委托书在第一步「提交材料」一并收集提交；进入「电子签章认证」步骤时不显示上传委托书模块（仅协议 + 验证码）。
2. **审核失败后**：电子签章步骤内展示「授权委托书审核未通过」结果态；点击「重新上传」进入**单独的委托书上传页**，**不回退到第一步提交材料**。
3. **阶段归属**：重传过程仍停留在「电子签章认证」这一步（StepBar 步骤索引不变）；重传完成后回到电子签章步骤启动新协议流程。

## 四、分析结论

1. **Web 端「CA 审核失败 → 重新上传 → 上传授权书页」是设计内行为**，与第二节口径及既有设计稿（阶段0 R-008 补充设计图「审核不通过提供重新上传操作」）一致，不构成前端缺陷。
2. 缺陷标题「应该跳转到审核失败页面」与已确认口径存在理解差异：审核失败结果态本就在电子签章步骤内展示，点击「重新上传」才进入上传页。需与 QA 核对截图停在哪一帧（是否漏看结果态、是否已点过「重新上传」）。
3. **APP 端跳「企业认证成功页」是独立问题**：APP 代码不在 wds-web 仓库，疑似只读实名 `authStatus=1` 而未判断审核态，需 APP / Server 侧定位（缺陷当前负责人盛瑞泽）。

## 六、独立风险观察（非本缺陷结论）

若待确认问题 2 的答案是「雇主实名终审不通过」，则存在另一条缺口（本轮只读发现，未修）：

- 雇主回显契约 `auditStatus` 仅定义 0=draft / 1=certified / 2=pending（`api/employer/certification/draft.types.ts` L42-43），适配器注释明确「Employer certification has no rejection state」，遇到 3 会抛「认证审核状态格式错误」（`employerCertificationDraftAdapter.ts` L122/L136）。
- 雇主认证容器 `applyDraftSnapshot` 无驳回恢复分支，`failure` 视图只能在提交过程中触发，刷新重进后到不了审核失败页。
- 服务商契约 `authStatus` 已有 3=审核失败（后端接口契约对齐表 L211），两端枚举不对称。
- 处置建议：先由 Server 明确雇主终审驳回的回显口径，再决定前端是否补 rejected 映射与恢复分支；确认前不落代码。
