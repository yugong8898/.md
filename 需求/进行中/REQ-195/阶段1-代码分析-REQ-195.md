## 分析范围与结论

- **需求编号**：REQ-195
- **项目**：`wds/wds-web`（Vue 3 + TypeScript + Ant Design Vue）
- **范围**：仅 Web PC；不分析或改动 APP、H5 与小程序。
- **结论**：现有认证流程位于 `views/provider/certification/index.vue`，通过 `ViewType` 状态机切换步骤组件（selectType → submitMaterials → faceVerify/moreInfo → signature → systemReview）。本次需求是在该流程中插入“电子签名认证”环节，而非新建独立认证页面。
- **补充设计图结论**：个人 / 法人从合同签署进入认证时采用弹窗；经办人采用“补充授权委托书”弹窗，并有审核中、审核不通过结果态。

## 现有认证链路

### 用户状态与实名状态

| 文件 | 现状 | 对 REQ-195 的影响 |
|---|---|---|
| `src/stores/user.ts` | 雇主用 `employer.employerInfo.authStatus`，服务商用 `currentProvider.providerInfo.authStatus`；二者只归一为已实名/未实名。当前服务商主体可经 `currentProviderId` 切换。 | 需新增主体级电子签章认证状态，不能与实名状态共用字段；多主体场景必须按当前主体重新获取。 |
| `src/composables/useCertCheck.ts` | `requireCert` 仅拦截平台实名和服务商开户，并以函数式 `CertModal` 引导原认证页。 | 可作为守卫组织方式参考，但不能直接用于电子签章认证。 |

### 原认证流程与可复用边界

| 文件 | 现状 | 可复用性 |
|---|---|---|
| `src/views/employer/certification/index.vue` | 个人流程为材料→人脸→旧协议签署；企业流程为材料→旧协议签署。 | 可参考步骤条、断点恢复与页面组织；不符合新协议阅读、短信验证码和经办人委托书审核流程。 |
| `src/views/provider/certification/index.vue` | 个人流程：材料→人脸→旧协议签署→审核；企业流程含完善信息。通过 `ViewType` 状态机切换，`currentStep` 计算当前步骤索引。**本次改动核心文件**：新增 `electronicSign` ViewType + Step 组件，在 `signature` 之前插入。 | 直接扩展，新增 ViewType 和对应组件。 |
| `src/views/authentication/components/ProtocolSignature.vue` | 拉取旧协议外链，`window.open` 后轮询 `userStore.fetchUserInfo()`，以 `authPhase` 判断签署成功。 | 可参考安全新开页和轮询清理；新电子签名认证组件需内嵌协议阅读、滑动提示、3秒倒计时、短信验证码。 |
| `src/views/authentication/components/CertEnterpriseSupplementSection.vue` | 已有授权委托书与经办人身份证补充材料上传能力。 | 仅可复用上传 UI/上传能力；爱签新版委托书的模板、提交、人工审核和审核意见需新接口与新状态。 |

## 合同签署入口

所有下列 PC 入口当前均直接进入旧合同流程或直接打开签署 URL，均为电子签章守卫候选入口。

| 角色 | 文件 | 当前行为 | 接入点 |
|---|---|---|---|
| 雇主 | `src/views/employer/contract/index.vue` | `handleSign` 跳合同确认页或直接打开 `item.url`。 | `handleSign` 开始处。 |
| 雇主 | `src/views/employer/order/list.vue` | `handleSignContract` 先查 `getEmployerContractBriefStatus`，再打开 URL、弹窗或进确认页。 | 查询成功、打开 URL 前。 |
| 雇主 | `src/views/employer/order/detail.vue` | 与订单列表同类的 `handleSignContract`。 | 签署动作开始处。 |
| 雇主 | `src/views/employer/purchase/buy.vue` | 下单后调用 `handleSignContract` 进入合同签署。 | 下单成功后的签署分支。 |
| 雇主 | `src/views/employer/order/general-contract/list.vue` | 二次确认后直接取得爱签 URL。 | 确认签署前。 |
| 雇主 | `src/views/employer/order/subpackageOrderActionService.ts` | 取得分包订单签署 URL 并新开页。 | `openSubpackageSignContractUrl` 开始处。 |
| 服务商 | `src/views/provider/contract/index.vue` | `handleSign` 调 `signProviderContract`，取得 `data.url` 后新开页。 | `handleSign` 开始处。 |
| 服务商 | `src/views/provider/order/list.vue` | 订单操作 `sign_contract` 调用签署处理。 | `handleSignContract` 开始处。 |
| 服务商 | `src/views/provider/order/detail.vue` | `handleSignContract` 调 `postProviderSignContract` 后新开页。 | `handleSignContract` 开始处。 |

**分析结果**：签署入口并非只存在于“我的合同 / 合同管理”。若只改合同列表，将遗漏订单列表、订单详情、下单后及分包订单等路径，导致同一主体在不同入口表现不一致。

## 接口与数据缺口

| 现有接口 / 数据 | 当前用途 | 与需求的差距 |
|---|---|---|
| `GET /.../employer/contract/briefStatus/{orderId}` | 雇主合同摘要与旧签署地址。 | 未证明返回主体级爱签认证状态，不能据此判断是否拦截。 |
| `POST /.../provider/orders/{orderId}/sign-contract`、`postProviderSignContract` | 服务商取得合同签署 URL。 | 目前直接返回 URL；需在调用前引入电子签章状态判断。 |
| `POST /.../employer/protocol`、`POST /.../provider/protocol` | 原认证链路的旧协议签署链接。 | 与本需求的新协议、验证码和爱签认证无接口契约证据，不能默认复用。 |
| `userStore.fetchUserInfo()` | 认证页完成后刷新实名及原认证阶段。 | 尚未包含电子签章状态的消费逻辑；新接口成功后需定义刷新 / 失效策略。 |
| 站内信 `content.path` | 通知跳转。 | 已支持路径跳转，但“回原合同继续签署”所需的订单、合同、主体和步骤上下文尚无约定。 |

## 建议改动范围

### 必改模块

1. `views/provider/certification/index.vue`：新增 `electronicSign` / `authLetterUpload` ViewType，修改 `personalSteps` / `businessSteps` 数组，调整 `currentStep` 计算逻辑和 `onMounted` 断点恢复逻辑。
2. 新增 `ProviderElectronicSign.vue` 组件：协议阅读 + 滑动提示 + 3秒倒计时 + 手机号验证码 + 提交。
3. 新增 `ProviderAuthLetterUpload.vue` 组件（经办人分支）：模板下载 + 文件上传 + 人工审核轮询 + 审核结果态。
4. 雇主与服务商所有合同签署入口的前置检查。
5. 6 个 PC 固定入口横幅接入。
6. 通知 `content.path` 的新路由消费。

### 可参考但不可直接复用的模块

- 原认证流程、`ProtocolSignature.vue`、`requireCert`、`CertEnterpriseSupplementSection.vue`。
- 原合同摘要和签署接口，仅用于定位合同入口；最终是否复用必须以新接口契约为准。

## 风险与待确认项

1. **高风险：签署遗漏**。合同入口跨合同页、订单页和下单后流程；守卫未统一会形成绕过路径。
2. **中风险：状态混淆**。平台实名 `authStatus`、旧认证流程 `authPhase`、新爱签状态不能混用。
3. **中风险：回跳丢失**。消息或认证完成后若未保留 `orderId` / `contractId`，无法满足“返回原合同继续签署”。
4. **待后端确认**：U-004、U-006、U-007；前端无法从现有源码推导新接口字段、委托书模板来源与协议链接契约。
5. **待产品 / 后端确认**：U-005；消息回跳参数的具体值。
