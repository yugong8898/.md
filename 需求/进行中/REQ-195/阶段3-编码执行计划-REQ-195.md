> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Web PC 端完成电子合同签章认证的状态、认证流程、合同签署守卫和固定入口接入。

**Architecture:** 以独立电子签章状态作为唯一业务状态源，不改写现有实名认证 `authPhase`。接口按 Server 最终契约复用、扩展或新增；认证组件、合同守卫和固定入口都只消费统一状态层。

**Tech Stack:** Vue 3、TypeScript、Vite、Ant Design Vue、Pinia。

## 全局约束

- 仅改动 `wds/wds-web` 的 Web PC 端；不处理 APP、H5 和小程序。
- 本期合同签署守卫仅覆盖雇主“我的合同”和服务商“合同管理”。
- 未确认 C-001、C-005、C-006、C-007 前，不落地推测字段或接口路径；U-009 按已确认的服务商主体关系处理。
- 不提交、不推送代码；每个编码步骤完成后执行对应验证。

> **适用范围**：仅 `wds/wds-web` 的 Web PC 端。本文只拆分执行步骤，不落地代码；实际编码以 Server 书面确认的 C-001、C-005、C-006、C-007 及已确认的 U-009 主体关系为依据。

**目标**：在不改变现有实名认证 `authPhase` 语义的前提下，完成电子合同签章认证在认证流程、两个核心合同入口及本期已明确的 PC 固定入口中的接入。

**实现原则**：电子签章状态使用独立状态语义；接口按业务能力复用、扩展或新增，不以候选接口数量作为实现约束；本期合同签署守卫只接入雇主“我的合同”和服务商“合同管理”。

## 步骤2：建立接口适配与统一状态源

- [ ] 按最终契约建立接口适配和统一电子签章状态源。

**执行目标**：把已确认的 Server 契约封装为唯一状态来源，供认证容器、合同守卫和固定入口共同消费。

**涉及文件**：

- `wds/wds-web/src/stores/user.ts`：本期不为 CA 状态扩展；现有主体 ID 和实名认证步骤字段继续按原用途使用

**执行内容**：

1. 按已确认的接口映射封装状态、协议、短信、认证完成和委托书业务能力。
2. 在 `useElectronicSignStatus.ts` 统一完成状态读取、刷新、入口状态映射和“认证成功”一次性曝光标记。
3. 以独立状态接口作为电子签章状态事实源；按 Server 方案兼容 `authPhase=4` 恢复检查点，不以它判断签署准入。
4. 为状态读取失败提供明确失败态，不把异常或空值判为已认证。
5. 在状态层内聚授权书审核结果轮询：`watch(entryStatus, { immediate: true })` 在 `entryStatus = 3`（审核中，入口不可点）时启动、非 `3` 时停止；每轮 `await refresh()`（GET `/status`）；递归 `setTimeout` 或 `inFlight` 防重入；失败只置 `error`、保留定时器并提供重试入口，不推断为审核失败（R-014-2）、`canSign=false` 不放行（R-014-5）；登录态转 false、主体切换、`onUnmounted` 三处清理。轮询频率以单一常量占位，U-011（频率与终止条件）待产品+后端确认后只改常量值；实现范式见 `.repoWiki/kb/wds-web/modules/views/authentication.md` 7.7，设计决策见阶段2「逻辑5」。

**验收效果**：

- 任一页面只通过 `useElectronicSignStatus.ts` 获取电子签章状态，不各自解析接口响应。
- 切换服务商主体后重新读取对应主体状态。
- 状态查询失败时，合同签署不放行；固定入口不展示误导性成功状态。
- 审核中态立即首查并按确认后的间隔持续刷新；审核通过/驳回后自动停轮询；切页、登出、主体切换后无残留请求，单轮超时不产生并发叠加。
